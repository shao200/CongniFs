## 0. 设计原则

| # | 原则 | 具体规则 |
|---|---|---|
| U1 | 极简、克制 | 无装饰性插画、无渐变、无拟人化头像；一屏只有一个主动作 |
| U2 | 信息分层，不堆叠 | 每条信息按「可见 → 展开 → 详情页」三级递进，默认只露第一级 |
| U3 | 单行工具栏 | 列表页只有一个工具栏：参数在左，操作在右；**不设第二层标题** |
| U4 | 适应窗口 | 三栏（侧栏/列表/详情）随宽度折叠为两栏、单栏；不出现横向滚动 |
| U5 | 侧栏可读性优先 | 非聚焦态侧栏使用深一档底色 + 1px 边线，文字对比度 ≥4.5:1；禁止白底白字 |
| U6 | 失败必须可见 | 降级、离线、证据缺失、预算耗尽，一律在界面上说明，禁止静默 |
| U7 | 不假装记得 | 没有记录就说没有；不确定就说不确定；引用必带日期与来源 |
| U8 | 破坏性操作两步 | 遗忘、批量删除、导出明文，一律「预览 → 确认」，并有回执 |
| U9 | 少动效 | 只保留 120–180ms 的淡入与位移；尊重 `prefers-reduced-motion` |
| U10 | 键盘可用 | PC 端所有主流程可全键盘完成，`?` 打开快捷键表 |

## 1. 信息架构

### 1.1 一级导航（PC）

```
┌──────┬──────────────────────────────────────────────────────────┐
│ 对话 │                                                          │
│ 知识库│                                                          │
│ 整理●│                    内容区（单栏或主从）                    │
│ 档案 │                                                          │
│ ──── │                                                          │
│ 设置 │                                                          │
└──────┴──────────────────────────────────────────────────────────┘
```

- 五项：**对话 / 知识库 / 整理 / 档案 / 设置**。不做「首页」「仪表盘」。
- 检索不再是独立导航，改为全局搜索框（`⌘K` / `Ctrl+K`），结果混合文档、分块、记忆与集合。
- 「整理」带待确认计数徽标；计数为 0 时不显示徽标。
- 侧栏可折叠为 56px 图标栏；折叠状态持久化。
- 侧栏底色比内容区深一档，选中项用高对比文字 + 左侧 2px 指示条。

### 1.2 一级导航（手机）

底部四个 Tab：**捕捉 / 对话 / 知识库 / 档案**；设置放在右上角。

- 理由：手机的高频动作是「说一句」「问一句」「查一下」；档案低频但必须可达。
- 「整理」不在手机底部；待确认建议以角标形式出现在「知识库」页顶部，点开只读。
- 不做「更多」抽屉，避免把功能藏起来。

### 1.3 双端功能分档（P0）

| 能力 | PC | 手机 |
|---|---|---|
| 对话（流式） | 完整 | 完整（精简布局） |
| 依据展开 | 完整（含未使用与原因） | 只读查看 |
| 知识库浏览 | 完整（树/列表/详情） | 只读列表 + 详情 |
| 整理建议 | 完整（预览/确认/撤销） | **只读**，不可确认 |
| 记忆档案 | 查看 / 修正 / 遗忘 | **只读** |
| 捕捉 | 文本 / 文件 / 截图 | 语音 / 文字 / 拍照 / 分享 |
| 检索 | 全局搜索 + 筛选 | 搜索框 + 结果列表 |
| 数据源管理 | 添加/暂停/移除 | 只读 |
| 设置 | 完整 | 只读 + 配对管理 |
| 批量操作 | 支持 | 不支持 |

## 2. 布局规范

### 2.1 断点

| 宽度 | 布局 |
|---|---|
| ≥1280 | 三栏：侧栏 + 列表 + 详情 |
| 1024–1279 | 两栏：侧栏 + 主区（详情覆盖或抽屉） |
| 768–1023 | 两栏收窄：图标侧栏 + 主区 |
| <768 | 单栏 + 底部 Tab |

所有页面高度撑满视口，内容区独立滚动，**页面本身不滚动**（避免工具栏被卷走）。

### 2.2 密度与字号

| 项 | 值 |
|---|---|
| 基准字号 | 14px；正文 15px；行高 1.65 |
| 列表行高 | 44px（紧凑）/ 56px（含副行） |
| 间距基数 | 4px；常用 8 / 12 / 16 / 24 |
| 圆角 | 6px（控件）/ 10px（卡片） |
| 内容最大宽度 | 对话 760px；档案详情 820px；居中 |

### 2.3 颜色语义

只使用语义色，不引入品牌渐变：

| 语义 | 用途 |
|---|---|
| `surface-1/2/3` | 内容区 / 侧栏 / 浮层 |
| `text-primary/secondary/tertiary` | 三级文字，对比度分别 ≥7:1 / 4.5:1 / 3:1（仅用于非关键信息） |
| `success` | 已通过保真度、已确认 |
| `warning` | 待复核、预算 80%、索引滞后 |
| `danger` | 遗忘、冲突未解决、硬失败 |
| `info` | 历史版本、演化提示 |

> 冲突不使用红色警报样式，用 `warning` + 双卡并列，避免制造焦虑。

## 3. PC 端关键界面

### 3.0 首次接入（P0 第一步）

```
第 1 步：选目录            第 2 步：扫描            第 3 步：首批建议
┌──────────────────┐   ┌──────────────────┐   ┌──────────────────┐
│ 选择一个目录       │   │ 已扫描 1,284      │   │ 发现 37 条建议     │
│ ▸ 文稿            │   │ 已解析 1,102      │   │ · 12 条归类        │
│ ▸ 下载            │   │ 失败 6（可查看）   │   │ · 9 条去重         │
│ [选择文件夹]       │   │ [暂停] [后台运行]  │   │ · 16 条关联        │
└──────────────────┘   └──────────────────┘   └──────────────────┘
```

- 一次只选一个目录，最多 3 个；默认不扫全盘。
- 选择后立即显示「只读接入，不会改名/移动/删除」。
- 隐私标签在接入时就要选（`llm_ok` / `local_only`），默认 `llm_ok`。
- 扫描可暂停、可后台；不阻塞用户先去对话。
- 失败文件单独成列表，标错误码；不混在「已完成」里。
- 第 3 步只展示建议数量与入口，不强制用户立刻处理。

### 3.1 会话页

```
┌─────────────────────────────────────────────────────────────┐
│ 会话标题（可编辑）        [模型: 云端]      + 新会话    ⋯     │  ← 单行工具栏
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   ┌───────────────────────────────────────────────────┐     │
│   │ 开场只加载 1 项：候选思想 2 条待确认  →  去确认      │     │  ← 开场卡
│   └───────────────────────────────────────────────────┘     │
│                                                             │
│   用户：这个方案还能怎么优化？                                 │
│                                                             │
│   助手：……                                                   │
│   依据 3 · 冲突 1 · 省流模式                                   │  ← 一行，可点开
│                                                             │
├─────────────────────────────────────────────────────────────┤
│ [输入框]                                      发送 ⏎         │
└─────────────────────────────────────────────────────────────┘
```

规则：

- **开场只呈现 1 项**，优先级：未确认候选 > 未解决张力 > 相关摘要（01 §J1）。用户处理或关闭后不再出现。
- 「依据」默认折叠为一行，点击从底部拉起抽屉，不跳页。
- 用户消息可点「追溯」查看它产生了哪些记忆。
- 助手回复超 2.5s 未出首字：显示骨架 + 「正在整理上下文」，不显示无限转圈。
- 流式中断：消息末尾标「已中断」，保留已生成内容，`partial=1`。

### 3.2 依据抽屉（Evidence Drawer）

```
┌───────────────────────────── 依据 ─────────────────────────────┐
│ 本次注入 3 条 · 未使用 4 条 · 预算 L1 412 / L2 188 / L3 40     │
├────────────────────────────────────────────────────────────────┤
│ L1  导师要求 11 月交初稿                          2026-09-12  │
│     「记住：导师要求11月交初稿」           查看原文 · 修正 · 遗忘│
│                                                                │
│ L2  SQLite 更适合单文件部署                        2026-09-20  │
│     「决定用 SQLite，不用 Postgres」       查看原文 · 修正 · 遗忘│
├────────────────────────────────────────────────────────────────┤
│ ▸ 未使用 4 条（为什么没提这件事）                                │
│    保真度未通过 2 · 证据缺失 1 · 仅本地内容 1                    │
└────────────────────────────────────────────────────────────────┘
```

- 每条必须显示：层、内容、日期、来源入口。
- 「未使用」必须可见，并把人话原因写出来（把 `reason_code` 翻译成中文）。
- 抽屉内可直接修正或遗忘，操作后回执在当前页轻提示，不跳走。

### 3.3 冲突双卡

```
┌───────────────────────┐  ┌───────────────────────┐
│ 2026-09-12            │  │ 2026-11-20            │
│ 「方案 B 更适合长期维护」│  │ 「方案 A 更稳妥」      │
│ 来源：会话 · 查看原文   │  │ 来源：会话 · 查看原文   │
└───────────────────────┘  └───────────────────────┘
  [旧的已过时]  [两条都对：不同时期]  [稍后处理]
```

- 两张并列，不标「对/错」，由用户裁决。
- 三个动作分别映射：`superseded`、保留为演化（关闭张力）、`稍后`（保持 open，30 天内不再提）。
- 同一对记忆 30 天内不再弹出。

### 3.4 质询条

位于输入框上方，窄条，一次只出现一条：

```
你 9 月 12 日说过「方案 B 更适合长期维护」，与现在的说法不一致。
[相关] [不相关] [已处理]
```

- 单场 ≤1 次、全天 ≤3 次（05 §3.4）；达到上限时不出现。
- 静默时段内不出现。
- 选择后立即消失，不追问理由。

### 3.5 记忆档案（三屏）

**第一屏 · 列表**

```
┌──────────────────────────────────────────────────────────────────────┐
│ [类型▾] [层▾] [状态▾] [时间▾]              导出   批量遗忘            │ ← 单行工具栏
├──────────────────────────────────────────────────────────────────────┤
│ ● 判断  「SQLite 更适合单文件部署」      L2  09-20  已确认  ▲3        │
│ ● 承诺  「导师要求 11 月交初稿」          L1  09-12  已确认  ▲7        │
│ ○ 偏好  「先给结论，再给理由」            L3  08-30  待复核           │
└──────────────────────────────────────────────────────────────────────┘
```

- 一行一条；类型用色点，不用图标墙。
- `▲3` 表示被注入次数，点击看引用记录。
- 默认按 `updated_at` 倒序；支持键盘上下移动 + 回车进入详情。

**第二屏 · 详情**

```
内容（可编辑）  「SQLite 更适合单文件部署」                    [保存]
──────────────────────────────────────────────────────────
证据
  2026-09-20 · 会话 · 「决定用 SQLite，不用 Postgres」  查看上下文
──────────────────────────────────────────────────────────
版本链
  v2  2026-11-02 由「Postgres 更好」修正为当前内容    查看差异
  v1  2026-09-20 创建
──────────────────────────────────────────────────────────
被引用
  会话摘要 2 · 注入记录 14 · 偏好 0 · 图边 4
──────────────────────────────────────────────────────────
[遗忘这条]  [仅删除来源事件]
```

- 证据必须一键定位到原文并高亮 `char_start/end`。
- 修正保存后立即生效，旧版本进版本链，可对比差异。
- 「遗忘」与「仅删除来源事件」分开，前者只删记忆，后者连带粉碎原话（05 §6.7）。

**第三屏 · 溯源**

点击「查看上下文」打开侧滑层，展示证据所在轮次的前后各 2 轮，命中片段高亮。层内可返回，不丢失列表位置。

### 3.6 遗忘流程

```
① 预览（弹窗）
   将遗忘 1 条记忆
   · 影响 3 个版本、18 条引用
   · 2 条摘要将被标记失效
   · 手机尚未确认
   · 备份中的副本将在 2026-12-26 到期
   [ ] 同时删除来源原话
   [取消]  [继续]
        │
② 确认（危险按钮，需 1.2s 长按或输入「遗忘」）
        │
③ 回执（独立页，可回看）
   ✓ 记忆条目   ✓ 引用   ✓ 向量   ✓ 图边   ✓ 视图
   ⧗ 手机待确认（已全局隐藏）
   备份副本到期：2026-12-26
```

- 回执页必须写出「哪些没删干净、为什么」，不允许只显示成功。
- 回执可从设置页「遗忘记录」再次打开。

### 3.8 整理收件箱

```
┌────────────────────────────────────────────────────────────────┐
│ [全部▾] [类型▾] [来源▾]              [全选] [拒绝] [确认 12]    │ ← 单行
├────────────────────────────────────────────────────────────────┤
│ ☐ 归类  3 份文档 →「齿科论文」                                    │
│    理由：路径含「齿科」且与 3 篇已有文献主题相似   置信 0.86       │
│    [预览影响]                                                    │
│ ☐ 去重  2 份重复 → 保留《方案 v2.pdf》                            │
│    理由：文本相似度 0.97，路径更短                    置信 0.94    │
│ ☐ 关联  《种植体综述》 ↔ 「项目 X」                               │
└────────────────────────────────────────────────────────────────┘
```

- 卡片只显示「动作 + 对象 + 理由 + 置信度」，详情在预览里。
- 「预览影响」展示：会改哪些条目、影响多少、能否撤销。
- 批量确认只允许低风险动作（打标、归类）；合并实体、标记重复必须逐条。
- 确认后卡片进入「已执行」，30 天内可撤销；撤销入口在卡片与回执页。
- 空态：「暂时没有需要你决定的整理」。不制造待办焦虑。
- 计数徽标与列表数量必须一致；不一致视为缺陷。

### 3.9 知识库浏览

```
┌────────────────────────────────────────────────────────────────┐
│ [搜索框] [类型▾] [来源▾] [只看未解析]        [新建集合] [刷新]    │ ← 单行
├──────────────┬─────────────────────────────────────────────────┤
│ ▾ 文档 1,284 │  《种植体周围炎诊疗共识》  PDF · 2026-09-12       │
│   ▾ 齿科  312│   3 章 · 42 块 · 已解析                          │
│   ▸ 项目 X 88│  《方案 v2》              DOCX · 2026-10-01       │
│ ▾ 集合   12  │   5 节 · 18 块 · 已解析                          │
│ ▾ 实体  204  │  《IMG_2043》             JPG · 未解析（仅元数据） │
└──────────────┴─────────────────────────────────────────────────┘
```

- 左树右列表，树懒加载；单节点超过 500 项提示「缩小范围」。
- 详情页三段：元数据 → 分块/原文 → 关联（实体、引用、相似文档）。
- 每个分块可「定位原文」；未解析文件只显示元数据与失败原因。
- 顶部搜索为全局搜索：文档、分块、记忆、集合混排，用类型徽标区分。
- 「只看未解析」是常用筛选，避免用户以为文件丢了。

## 4. 手机端

### 4.1 捕捉（默认页）

- 一个主按钮：按住说话；松手即存。左右滑切换「文字 / 拍照」。
- 完成后 Toast：「已记录 · 撤销（5s）」。
- 离线时按钮形态不变，仅顶部显示「离线，稍后同步」；不阻断操作。
- 转写失败：保留音频，条目显示「待转写」，可重试。

### 4.2 对话

- 与 PC 同一套组件，隐藏侧栏与批量操作。
- 依据只读；点开可见来源，不可修正（引导到 PC）。
- 顶部常驻一行状态：在线 / 离线 / 省流模式。

### 4.3 只读档案

- 列表 + 详情，无编辑与遗忘按钮，底部提示「在电脑上修改」。
- 搜索可用，依赖 PC；PC 离线时只搜本地缓存的最近 200 条，并明确标注范围。

### 4.4 配对与证书引导（必须一屏走完）

```
① 用手机相机扫描电脑上的二维码
② 按提示安装本地证书（一次性）
③ 输入电脑上的 6 位配对码

[不想安装证书？使用网页版（不可安装、无离线）]
```

- 每步都有「上一步 / 跳过」；跳过则进入降级说明，而不是死路。
- 失败时给出具体原因（证书未信任 / 不在同一网络 / 码过期），不显示错误码原文。

### 4.5 离线态

| 场景 | 表现 |
|---|---|
| 无网络 | 顶部条「离线」，捕捉可继续，对话禁用并说明原因 |
| PC 关机 | 「电脑不在线」，仅显示缓存与未同步内容 |
| 同步中 | 顶部细进度条，不阻塞操作 |
| 同步冲突 | 不弹窗；以事件追加为准，界面无需提示 |

## 6. 文案规范

| 场景 | 必须这样写 | 禁止 |
|---|---|---|
| 没有相关记录 | 「没有找到相关记录」 | 「我好像记得……」 |
| 证据缺失 | 「这条记忆的来源已无法定位，已停止使用」 | 静默跳过 |
| 隐私阻断 | 「本次回答未使用云端模型：内容含仅本地项」 | 「出错了」 |
| 预算降级 | 「本月额度已用完，当前为省流模式」 | 无提示地变慢变短 |
| 遗忘未完成 | 「已从 7 处清理 6 处；手机尚未确认；备份副本将于 X 日到期」 | 「已彻底删除」 |
| 冲突 | 「你 9 月 12 日说过……与现在不一致」 | 「你错了」「你变了」 |
| 手机只读 | 「在电脑上可修改」 | 灰掉按钮却不解释 |

所有涉及「关于你」的陈述，必须带日期 + 原文入口（A4）。

## 7. 状态与反馈

| 状态 | 视觉 | 文案 |
|---|---|---|
| 加载 | 骨架屏，3 行 | 无 |
| 流式生成 | 光标 + 逐字 | 无 |
| 首字延迟 >2.5s | 骨架 + 一行说明 | 「正在整理上下文」 |
| 部分完成 | 消息尾标「已中断」 | 可重试 |
| 离线 | 顶部细条 | 「离线，稍后同步」 |
| 省流模式 | 顶部细条 + 每条回复角标 | 「省流模式」 |
| 索引滞后 | 搜索框下细提示 | 「部分内容暂不可检索」 |
| 空态 | 一行说明 + 一个动作 | 见下 |

空态文案：

- 档案空：「还没有记忆。对话结束后会自动生成待确认项。」
- 检索空：「没有找到。试试更短的关键词，或切换到『全部时间』。」
- 候选空：不显示空态，直接隐藏该卡片。

## 8. 可访问性与响应式

- 对比度：正文 ≥4.5:1，侧栏文字 ≥4.5:1，禁用态 ≥3:1 且不只靠颜色区分。
- 焦点：所有可交互元素有 2px 焦点环，Tab 顺序与视觉一致。
- 快捷键：`⌘K` 搜索、`⌘N` 新会话、`⌘,` 设置、`?` 快捷键表、`Esc` 关闭抽屉。
- 动效：≤180ms；`prefers-reduced-motion` 下全部改为无动画。
- 触控：手机最小点击区 44×44。
- 缩放：200% 下不出现横向滚动。

---

## 9. 性能相关的体验约束

- 列表超过 200 条启用虚拟滚动。
- 抽屉与详情用懒加载，首屏只取列表字段。
- 流式渲染按帧合并，避免逐字触发重排。
- 视图切换不整页刷新，只替换左侧分组与右侧列表。
- 任何操作的可感知延迟 >300ms 必须有中间反馈。
