## 一页纸摘要

1. **这是一个产品，不是两个。** 第一版的「多维虚拟目录」是**视图引擎**，第五版的「可审计附脑」是**记忆引擎**，二者共用同一份原子存储与检索内核，在同一个入口以不同视图呈现。**已决策：合并为一个产品**；文件知识库不进入首期，但数据模型从一开始就预留 `asset` 原子，避免二次改表。
2. **最强的架构统一是：一切皆事件，一切视图皆投影。** 第一版的「文件是原子，目录是视图」这条原则，可以原样推广到第五版的「对话流 / 思想流 / 记忆 / 图谱」——它们不该是四套并行的数据，而应是同一份事件日志的不同投影。这一条同时解决 v5 里双流数据模型不完整、审计难溯源、视图难扩展三个问题。
3. **v5 最大的漏洞不在功能，在三条链没闭环：记忆链（写入）、注入链（使用）、遗忘链（删除）。** v5 只补了第一条链的一半。本文把三条链都定义为可验证的机制，并统一采用 **fail-closed（证据缺失就不注入、审计失败就不记忆）**。
4. **放弃「手机端完整本地 T0」这个不现实的目标**，改为「手机瘦客户端 + PC 作个人边缘服务器 + 局域网/加密隧道直连」。这一改动让手机端从「架构冲突」变成「可交付」，也让 local_only 承诺真正成立。
5. **首期双端并行，但功能分档。** **已决策：双端并行。** 两端共用一套 API：PC 端全功能（审计、修正、遗忘、注入回执）；手机端只做捕捉、对话与只读审计。并行不是把功能写两遍，而是把同一套接口接到两种外壳上。文件知识库、图谱、WinFsp 全部后置。

## 1. 判断：这到底是什么系统

### 1.1 两份来源的真实关系

| | 第一版（虚拟目录） | 第五版（Extensa v5） |
|---|---|---|
| 处理的原子 | 文件（PDF/文档/图片） | 事件（对话、判断、捕捉） |
| 核心价值 | 同一批文件，多维度投影 | 同一个人，跨会话连续记忆 |
| 关键机制 | 规则/语义/实体/关联视图 | 分层注入 / 审计 / 质询 |
| 数据底座 | SQLite + 向量 + 图 | SQLite + 向量 + 图 + 事件流 |
| 用户动作 | 找东西、看全局 | 对话、被提醒、查账 |

结论：**它们不是竞品，是同一内核的两个出口**。文件是「外部世界的原子」，事件是「你内心的原子」；目录是文件原子的投影，记忆是事件原子的投影。既然投影同源，就应该是一个产品——**已决策合并**。

注意一个容易被忽略的工程含义：合并意味着**数据模型从第一天就要容纳两类原子**（`event` 与 `asset`），即使首期只实现 `event`。否则第二阶段接入文件时会动到记忆表与注入管线。这是「先不做什么」与「先想清楚什么」的区别，必须在 **01 产品定位与边界** 与 **04 领域模型** 里同时体现。

### 1.2 一句话定位（建议）

> 一个本地优先、可审计的个人认知系统：把你说过的话、做过的判断、读过的文件，沉淀为一份只增不改的事件账本，再按需投影成对话记忆、思想流、知识目录与关系图谱——并且你随时能查、能改、能忘。

### 1.3 公理（在 v5 四公理上收敛，并新增一条工程公理）

| 编号 | 公理 | 落到设计上的硬约束 |
|---|---|---|
| A1 | **连续性**：理解跨会话累积 | 会话结束必须产出可注入的结构化记忆，否则视为失败 |
| A2 | **可对话性**：主动性只发生在对话里 | 禁止无对话场景的广播推送（定时摘要默认关） |
| A3 | **情境性**：联想以「此刻的任务」为锚 | 所有检索必须有当前语境锚点，无锚点不主动联想 |
| A4 | **可审计性**：关于你的记忆必须可查、可溯源、可改、可忘 | 无 evidence 的记忆不进入注入管线；无回执的遗忘视为未完成 |
| A5 | **可逆性（新增）**：任何系统动作都必须可撤销 | 记忆有版本、注入有回执、删除有墓碑、批量操作有预览 |

A5 是工程公理而非产品愿景，但它决定了**所有写路径都要先设计读路径和删路径**。v5 的 `forget()` 只是把它写在了功能清单里，没有变成全局约束。

### 1.4 明确的非目标

- 不做多用户 / 团队协作 / 组织权限。
- 不做通用笔记软件（不替代 Obsidian，只做它的上游索引与旁路）。
- 不做全自动整理物理文件夹（物理层永不被改写）。
- 不做人格画像、心理测评、情绪陪伴类功能。
- 不做云端托管的多租户服务（可选自建同步，但不是 SaaS）。

## 2. 诊断：保留 / 改造 / 砍掉

| # | v5（或 v1）原设计 | 我的判断 | 处理 |
|---|---|---|---|
| 1 | L1/L2/L3 按 token 预算分层 | 分层是对的，但**预算不是分类**。它只决定「放哪、放多少」，不决定「这记忆是什么、怎么衰减、怎么冲突」 | **改造**：引入记忆类型（事实/偏好/判断/承诺/关系/事件），类型管生命周期，层管注入位置，两维正交 |
| 2 | `evidence_json` 塞进记忆条目 | 这是审计的地基，不能是个自由 JSON | **改造**：独立 evidence 记录（来源类型、来源 ID、字符区间、原文摘录、时间、生成模型、提示词版本） |
| 3 | `memory_entries.version` 保留历史 | 版本号不足以回答「三个月前系统眼中的你」 | **改造**：双时态（valid_time / transaction_time），可精确回放任一时刻的认知快照 |
| 4 | `forget()` 级联删除 | 只写了「删摘要、删注入项、删引用」，漏了向量、图谱边、物化视图、其他设备副本、备份 | **改造**：七步级联清单 + 墓碑 + 备份保留期的如实告知 + 回执校验 |
| 5 | 摘要保真度「每月抽检 10 条」 | 方向对，但「严重歪曲一票否决」没有可操作定义，也没说否决后冻结什么范围 | **改造**：定义判定协议、严重歪曲的四类判定、冻结粒度到「生成器版本」而非整个系统 |
| 6 | 张力 = 相似度阈值 + 语义对立检测 | 这是全系统最含糊的一处，也是最容易变成骚扰的一处 | **改造**：给出张力分数公式、去重键、跨会话总预算、静默时段、三态反馈 |
| 7 | 手机端「T0 等价层」本地跑嵌入 + whisper | PWA 在 iOS 上无法稳定后台运行 whisper-small；端侧向量库维护成本极高；这条路会把项目拖死 | **砍掉，改架构**：手机做瘦客户端，PC 做边缘服务，局域网/加密隧道直连；local_only 内容不出局域网 |
| 8 | 开场「只加载 1 项」 | 正确，但没说选哪一项的规则 | **保留并具体化**：按「未确认候选 > 未解决张力 > 相关会话摘要」优先级 + 时间衰减 |
| 9 | T1.5 升格为云端对话主模型 | 正确。3B 撑不住复合任务 | **保留**，但补充：断网/超预算时的降级矩阵要写死，不能现场发挥 |
| 10 | 四表图谱 + 虚拟目录引擎「继承」 | 已确认：**不存在，全部重写** | **改写**：路线图按零资产重排，删除所有「继承」假设；顺序改为「先内核、后能力」，不做能力先行、内核补票 |
| 11 | 虚报目录三种落地形态 A/B/C | B（本地 Web）是对的起点，C（WinFsp）是陷阱 | **保留 B 为 P0，C 降为可选实验**；A（符号链接树）仅作为导出功能，不做常驻 |
| 12 | 定时摘要默认关 | 正确 | **保留**，但纳入「静默模式」总开关 |
| 13 | 「人格倾向」用户模型维度 | 已经自己否掉了，好 | **固化**：只存单次决策记录，禁止聚合出性格标签 |
| 14 | 多端同步 | v5 通篇没写，这是最大工程缺口 | **新增**：事件日志 + 设备副本 + 冲突合并策略（见 3.4） |
| 15 | 加密与传输安全 | v5 只有「脱敏正则」，没有静态加密与传输方案 | **新增**：静态加密（SQLCipher）、局域网 TLS、无遥测 |

## 3. 核心架构主张（五条）

这五条是本文最需要你认同的部分。它们决定了后面所有文档的骨架。

### 主张一：一切皆事件，一切视图皆投影

把 v1 的「文件是原子，目录是视图」升格为全局原则：

```
原子层（唯一真相，只增不改）
  事件 event ──┬─► 会话记忆投影（按 session 聚合）
  文件 asset ──┼─► 思想流投影（按 origin=judgment 过滤）
               ├─► 记忆条目投影（按类型 + 有效期）
               ├─► 虚拟目录投影（按 tag/entity/time 分组）
               └─► 图谱投影（按实体共现/引用建边）
```

收益：

- **审计天然可行**：任何一条记忆都能回指到产生它的事件，事件不可变。
- **双流问题消失**：不再有「对话流」和「思想流」两套存储要同步，只有一个事件流 + 两个视图。
- **视图可无限扩展**：加一种视图 = 加一个投影函数，不动存储。
- **可重建**：投影损坏可以直接从事件日志重放。

代价与克制：不做完整 CQRS，不搞消息总线。**事件日志 + 物化视图表**两层即可；投影允许异步，允许丢，可以从日志重建。

### 主张二：记忆的两个正交维度

v5 把「分层（L1/L2/L3）」当成了记忆的分类，这是概念混淆。正确的模型是：

| 维度 | 取值 | 决定什么 |
|---|---|---|
| **类型**（语义） | 事实 F / 偏好 P / 判断 J / 承诺 C / 关系 R / 事件 E | 生命周期、衰减速度、冲突规则、是否需要 evidence |
| **层**（注入） | L1 常驻 / L2 检索 / L3 常量 | 位置、token 配额、更新时机 |

举例：一条「导师要求 11 月交初稿」是 **类型 C（承诺）+ 层 L1**，带截止时间，过期自动降权；一条「偏好结论先行」是 **类型 P + 层 L3**，90 天半衰期。二者都可能在 L1，但衰减与冲突规则完全不同。

> 这张表是 04 / 05 两篇文档的共同地基，必须先定死。

### 主张三：审计要覆盖三条链，而不只是记忆本身

v5 只做了「记忆档案」（记忆链）。真正让用户敢信任的，是三条链都能查：

| 链 | 用户的问题 | 需要的机制 | v5 状态 |
|---|---|---|---|
| **记忆链** | 你记了我什么？从哪来的？ | 记忆条目 + evidence + 双时态 | 部分有 |
| **注入链** | 你这次回答，用了哪几条关于我的记忆？ | **注入回执**（injection receipt），每条回复可展开 | **缺** |
| **遗忘链** | 我删掉的，真的消失了吗？ | 墓碑 + 级联清单 + 删除回执 + 备份披露 | 只有一行 `forget()` |

注入链是我要强补的：**没有注入回执，用户永远无法解释「系统为什么会这么说」**，记忆档案就只是个只读清单。

### 主张四：端是瘦客户端，PC 是个人服务器

```
        ┌──────────── PC（个人边缘服务器）────────────┐
        │ 事件日志 · 记忆库 · 向量索引 · 模型调度      │
        │ 局域网 HTTPS 服务（Tailscale / 自签证书）     │
        └───────┬──────────────────────┬──────────────┘
                │ LAN / 隧道            │ 本机
        ┌───────▼────────┐      ┌──────▼───────┐
        │ 手机 PWA        │      │ PC 桌面端     │
        │ 捕捉 + 检索 + 对话│      │ 全功能工作台  │
        │ 离线队列 + 本地缓存│      │              │
        └────────────────┘      └──────────────┘
```

关键取舍：

- 手机**不跑嵌入模型**，检索请求打到 PC；PC 不在线时退化为「关键词 + 本地缓存的最近 N 条」。
- `local_only` 内容**只走局域网/隧道**，永不进公网 API；需要云端生成时，走敏感网关，默认拒绝。
- 语音转写优先用系统听写，其次云端（并标记隐私等级），最后才是端侧 whisper（能力允许时）。
- 这比「手机独立 T0」现实得多，也不牺牲隐私承诺。

### 主张五：失败关闭（fail-closed）

系统的默认动作必须是「不做」，而不是「尽力而为」：

| 场景 | 失败关闭行为 |
|---|---|
| 记忆条目 evidence 无法解析 | 不注入，降级为普通对话 |
| 摘要 fidelity 未通过 | 不进入 L2，只在记忆档案里可见并标记 |
| 两条记忆冲突且未仲裁 | 两条都注入并标注「存在冲突」，不静默择一 |
| forget 未收到所有设备回执 | 该条目在所有视图强制隐藏，状态标记「删除中」 |
| 云端预算超限 | 停 T2，对话降级 T1 并明确告知，不静默降质 |
| 手机离线且无缓存 | 明确提示「离线，无法检索历史」，不编造 |

这条主张写进 05 与 09，作为代码评审的检查项。

## 4. 总体架构

```
┌──────────────────────── 交互层（瘦） ────────────────────────┐
│  PC 工作台（Next.js/Tauri）    手机 PWA        悬浮助手（降级三级）│
└───────────────────────────────┬─────────────────────────────┘
┌───────────────────────────────▼─────────────────────────────┐
│ 会话编排层                                                    │
│  语境构建 → 记忆注入 → 质询决策 → 生成 → 注入回执 → 异步摘要     │
└───────────────────────────────┬─────────────────────────────┘
┌───────────────────────────────▼─────────────────────────────┐
│ 投影层（视图）                                                │
│  会话记忆 · 思想流 · 虚拟目录 · 图谱 · 用户偏好常量             │
│  全部从事件日志 + 资产表投影而来，可重建                        │
└───────────────────────────────┬─────────────────────────────┘
┌───────────────────────────────▼─────────────────────────────┐
│ 原子层（唯一真相）                                            │
│  event log（只增） · asset（文件） · evidence · 墓碑            │
│  SQLite（加密） + FTS5 + 向量索引 + 图边表                     │
└───────────────────────────────┬─────────────────────────────┘
┌───────────────────────────────▼─────────────────────────────┐
│ 能力层                                                        │
│  T0 本地检索/转写 · T1 批量打标 · T1.5 对话 · T2 摘要/矛盾      │
│  预算闸门 · 脱敏网关 · 隐私分级 · 设备同步                     │
└─────────────────────────────────────────────────────────────┘
```

四条主数据流：

1. **接入流**（v0.4 主干）：源（目录/MCP）→ 扫描 → 解析 → 分块 → 索引 → 知识库 → 整理建议。
2. **捕捉流**：语音/文字/文件 → 事件写入 → 异步打标 → 投影（思想流/目录）。
3. **对话流**：输入 → 语境构建（世界知识 + 用户知识）→ 注入 → 生成 → 注入回执 → 会话结束异步摘要 + 候选思想。
4. **审计流**：用户打开档案/知识库 → 查询投影 → 展示 evidence 与版本 → 修正/遗忘 → 级联 + 回执。

**单产品形态说明**：一个入口、一套数据、一个检索框。文件与事件落在同一个检索结果里，按「相关度 × 类型权重」混排。虚拟目录是 `asset` 的投影，思想流是 `event` 的投影，在 UI 上并排为两个视图，而不是两个子系统。`asset` 在 P0 即启用，不再后移。

## 5. 领域模型与关键不变量

（完整表结构留给 04，这里只定骨架与约束。）

### 5.1 六种原子

| 原子 | 说明 | 是否可变 |
|---|---|---|
| `event` | 发生的事：一句话、一次捕捉、一个判断、一次修正、一次遗忘 | 不可变，只能追加 |
| `asset` | 文件/图片/音频，物理路径唯一真相 | 内容按 hash 不可变，元数据可投影 |
| `evidence` | 记忆的证据指针 | 不可变 |
| `tombstone` | 被遗忘对象的墓碑（id + hash） | 不可变，防复活 |
| `projection` | 物化视图（记忆条目、目录节点、图边） | 可重建 |
| `receipt` | 注入回执 / 删除回执 | 不可变 |

### 5.2 双时态

每条记忆带两个时间轴：

- `valid_time`：这条判断在**你的认知里**成立的时间区间（例如「9 月我认为方案 B 更好」）。
- `transaction_time`：系统**记录/修正**它的时间。

于是「三个月前系统眼中的你」= `transaction_time ≤ T 且 valid_time 包含 T` 的快照。这是 v5 里一句浪漫的话变成可执行查询的唯一办法。

### 5.3 三个生命周期状态机

**记忆条目**：`proposed → active → (corrected | superseded | forgotten)`
- 只有 `active` 可进入注入管线。
- `corrected` 保留旧版本链，不删除。
- `forgotten` 内容清空，保留墓碑。

**候选思想**：`pending → (confirmed | edited | expired)`，默认 30 天过期。

**张力（冲突）**：`open → (resolved_by_user | dismissed | auto_resolved | stale)`，必须可查，未解决的张力是质询的唯一来源。

### 5.4 十五条不变量（评审清单）

| 编号 | 不变量 |
|---|---|
| I1 | 事件表只允许 INSERT，禁止 UPDATE/DELETE |
| I2 | 任何 `active` 记忆必须有至少一条可解析的 evidence |
| I3 | 任何注入项必须能追溯到 `memory_id` + `evidence_id` |
| I4 | `fidelity != pass` 的记忆不得进入 L2 |
| I5 | `privacy=local_only` 的内容不得出现在发往公网的请求体中（由请求体扫描器强制） |
| I6 | `forgotten` 对象在全部投影视图不可见，即使投影尚未重建 |
| I7 | 同一 `valid_time` 区间的两条矛盾判断必须产生一条 `tension` 记录 |
| I8 | 每条回复最多 1 次主动质询，全天 ≤3 次 |
| I9 | 所有 LLM 调用必须写 `llm_tasks`（层、模型、token、成本、prompt 版本、输入哈希） |
| I10 | 任何「关于用户」的结论不得由系统单独生成并直接 `active`，必须经过用户确认或显式标记 `inferred` |
| I11 | 原始音频默认不落盘；开启留存时上限 7 天且可一键清除 |
| I12 | 巩固产出的推断不得直接 `active`，且每次巩固必须留 `consolidation_runs` 记录 |
| I13 | 旁观者数据不做身份识别，说话人仅保留匿名标签 |
| I14 | 源文件只读：禁止改名、移动、删除源文件 |
| I15 | 整理建议必须人确认且可撤销 |

I10 是对 v5「只存用户确认的事实」的机械化表达——原文是原则，这里变成字段与闸门。

## 6. 关键机制具体化

这一节是把 v5 里最含糊的六处写到可施工的程度。详细协议在 05 / 07 中展开，这里给决策。

### 6.1 会话摘要与候选思想

- **输入**：整场对话的原始轮次（不是上次摘要，避免误差累积）。
- **输出**：严格 JSON，字段与 v5 一致，但补三个：`inferred_facts`（系统推断，默认不进 L1）、`evidence[]`（每条判断对应原文轮次 ID）、`confidence`。
- **禁止项**：不得改写用户原话作为「用户判断」；不得把系统的建议写进 `user_judgments`；不得生成性格评价。
- **候选思想**：只从 `user_judgments` 与 `explicit_remember` 中提取，标注 `source: conversation, status: pending`，单场最多 5 条。

### 6.2 保真度闸门协议

| 项 | 定义 |
|---|---|
| 抽样 | 每周随机 10 条 + 全部 `confidence<0.6` 的条目 |
| 判定 | 用户三选一：忠实 / 轻度偏差 / 严重歪曲 |
| **严重歪曲的四类** | ① 系统声称用户说过但用户从未说；② 把否定说成肯定；③ 张冠李戴（他人观点记为用户）；④ 编造具体数字/日期/承诺 |
| 触发后果 | 单条 → 立即 `corrected` 并禁止注入；同类问题累计 2 次 → 冻结**该摘要生成器版本**（prompt+模型组合），回滚到上一版本重跑近 7 天摘要；不冻结整个系统 |
| 通过标准 | 周「无歪曲率」≥80% 且严重歪曲 = 0 |

> 原文的「一票否决、整体暂停注入」粒度太粗，会让一次误判停掉整个产品；改为**按生成器版本冻结**，可定位、可回滚。

### 6.3 冲突检测与质询预算

```
张力分数 tension = sim × contradiction × recency × stake
  sim           语义相似度（余弦，阈值 ~0.72）
  contradiction 对立判定（NLI / LLM 二分类，仅当 sim 达标才调用，省成本）
  recency       exp(-Δt / 180d)
  stake         类型权重：J=1.0, C=0.9, P=0.5, F=0.3
触发质询：tension > θ（初始 0.55，自适应）
```

| 约束 | 值 |
|---|---|
| 单场对话 | ≤1 次 |
| 全天 | ≤3 次（跨会话总预算，v5 缺） |
| 静默时段 | 用户可设（默认 23:00–08:00 不质询） |
| 捕捉模式 | 永不质询 |
| 去重 | `hash(memory_a, memory_b)` 已呈现过则不再提，除非用户标记「稍后处理」 |
| 反馈 | 三态：相关 / 不相关 / 已处理；「已处理」直接关闭张力 |
| 自适应 | 不相关率 >50% → θ 上调一档；连续 3 次相关 → 下调一档 |

### 6.4 注入管线与注入回执

**管线**：候选集 → 过滤 → 打分 → 预算裁剪 → 冲突检查 → 写回执 → 拼装。

1. **候选**：L1 全量 + L2 向量 top-20 + L3 常量。
2. **过滤**（fail-closed）：evidence 可解析、`fidelity=pass`、状态 `active`、隐私等级允许当前出口、未过期。
3. **打分**：`相关度 × 重要度 × 新鲜度(按类型衰减)`。
4. **裁剪**：按层配额（500/300/100 token）贪心选取 + MMR 去冗余。
5. **冲突检查**：命中未仲裁冲突 → 两条都留，附 `conflict` 标记。
6. **回执**：写 `injection_log`（turn_id、memory_id、层、rank、token、reason、evidence_ok）。

**UI 契约**：每条回复可展开「这次的依据」，列出被注入的记忆条目及其来源。这是 v5 完全缺失、但信任感最关键的一块。

### 6.5 forget() 七步级联与回执

1. `memory_entries` → `forgotten`，正文清空，保留墓碑（id + content_hash）。
2. `memory_refs` 反向索引 → 找出所有引用它的摘要、注入项、用户偏好条目。
3. 向量索引 → 删除向量，写入墓碑防重算回填。
4. 图谱边 → 删除相关边。
5. 物化视图 / 缓存 → 失效重建。
6. 其他设备 → 下发遗忘指令，收集 ack（超时则该条目全局强制隐藏）。
7. 备份 → **如实披露**：备份中的副本将在保留期 N 天后自然过期，回执中明确写出，不假装已删除。

回执内容：删了什么、影响了几条引用、哪些设备已确认、备份保留截至日期。**没有回执的遗忘视为未完成**（I6）。

### 6.6 多维虚拟目录

- **投影 DSL**（内部）：`view := groupby(dim) | filter(pred) | order(key) | limit(n)`，dim ∈ {time, ext, tag, entity, project, source}。
- **四类视图**：规则（mtime/扩展名/路径关键词）→ 语义（tag 聚类）→ 实体（entity 共现）→ 关联（图 1–2 跳）。
- **落地形态**：知识层接入阶段（P3）先做「本地 Web 浏览器 + 规则视图 + 标签视图」；WinFsp 挂载与符号链接树列为可选实验，不进主路径。
- **与记忆共用**：`tag` / `entity` / `edge` 三张表同时服务文件视图与记忆图谱——这就是「一个索引库，三种消费方式」的落地。首期建表时即按此设计，避免 P3 改表。

## 9. 评测与闸门

### 9.1 金标集

30 个场景，覆盖：单轮判断、多轮改主意、明确否定、时间演化、他人观点误记、隐含偏好、承诺与截止时间、冲突未解决、遗忘后残留、跨会话引用。每个场景 4–6 条断言，作为回归测试。

### 9.2 指标

| 指标 | 定义 | 目标 |
|---|---|---|
| 抽取精确率 | 记入 `user_judgments` 的条目中，用户认可的比例 | ≥85% |
| 归因准确率 | 记忆能正确回指原文轮次的比例 | ≥90% |
| 幻觉引用率 | 引用了不存在的原文 | **必须 0** |
| 冲突召回率 | 金标集中应被发现的矛盾被检出比例 | ≥70% |
| 冲突精确率 | 报出的冲突中真实存在的比例 | ≥60% |
| 注入相关性 | 人工 1–5 分，注入项是否帮助了本次回答 | ≥4.0 |
| forget 完整率 | 级联检查脚本在 7 个存储位置全部通过 | 100% |
| 成本 | 每千轮对话总成本 | 按预算表 |

### 9.3 闸门判定

- 任一指标未达标 → 不进入下一阶段。
- 「幻觉引用率 > 0」与「forget 完整率 < 100%」为**硬否决**，优先级高于一切功能推进。

## 12. 本质重构：本机数据 → 私有知识库 → AGI

> **用 MCP 把数据接进来，在本机建成可审计的私有知识库，由 AGI 代理持续整理，并在你确认后改变知识结构。**

四层：

```
接入面：本机文件/媒体 · 本机应用数据 · MCP 外部数据源（只读）
知识面：文档 · 分块 · 实体 · 关系 · 事实 · 集合（私有知识库）
整理面：分类 · 去重 · 合并 · 关联 · 摘要 · 建集合（建议 + 人确认）
智能面：代理（规划 · 检索 · 工具 · 校验 · 反思 · 回滚）
```

三项结构性修正：

1. **D4 作废**：P0 必须包含本机数据索引，否则「整理」无从谈起。
2. **记忆降为子集**：知识库是主体，用户记忆是其中「关于你」的一页。
3. **AGI 落地为代理工作流**：不做通用智能宣称；以规划—工具—校验—回滚的闭环实现，MCP 是手和感官。

P0 重定义：文件接入 → 解析分块 → 私有知识库 → 整理建议 → 检索问答；对话作为入口；MCP 先接 1 个只读连接器。

> 这不是窄义的「检索增强生成」，而是**知识中心 RAG（L4）**：接入、结构、整理、检索、反馈五个闭环缺一不可。多数 RAG 产品只做到「切块 + 向量 + top-k」，那是演示，不是大脑。
>
> 决策记录见 `adr/0008-数据优先与知识中心RAG`；实现细节见 01 §1.4、03 §3.7、05 §6B、07 §9、09 §4A、10 §6B/6C、11 §2。

## 附录 A · 术语表（初稿）

| 术语 | 定义 |
|---|---|
| 原子 | 不可再分的真相记录（事件、文件、证据、墓碑） |
| 事件 | 一次发生的动作或陈述，只增不改 |
| 投影 | 从原子层计算出的物化视图，可重建 |
| 记忆条目 | 投影的一种，带类型、双时态、evidence、fidelity |
| 张力 | 两条记忆/判断之间的实质矛盾，可追踪、可关闭 |
| 注入回执 | 记录某次回答使用了哪些记忆的记录 |
| 删除回执 | 记录一次 forget 影响范围与设备确认状态的记录 |
| 保真度 | 摘要/记忆相对原始对话的忠实程度 |
| 失败关闭 | 条件不满足时系统选择不执行，而非降级执行 |
