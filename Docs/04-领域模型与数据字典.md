## 0. 建模原则

| # | 原则 | 落地 |
|---|---|---|
| M1 | 骨架不可变，内容可粉碎 | `events` 只存元数据且禁止 UPDATE/DELETE；正文在 `event_payloads`，遗忘时销毁密钥 |
| M2 | 一切可从事件重放 | 除 `events` / `devices` / `settings` 外，其余表都标注「是否可重建」 |
| M3 | 双时态 | 所有记忆条目带 `valid_from/to` 与 `tx_from/to` |
| M4 | 遗忘是数据，不是删除 | `tombstones` 保留 id + 内容哈希，防重放复活 |
| M5 | 枚举用 CHECK，不用魔法字符串 | 所有状态字段必须 CHECK |
| M6 | 时间统一为 UTC 毫秒整数 | `*_at` 全部为 `INTEGER`（Unix epoch ms） |
| M7 | 主键统一 ULID | 26 字符、时间可排序、可离线生成 |
| M8 | JSON 只存不可查询的附属信息 | 需要筛选/排序的字段必须独立成列 |

## 2. 关键设计：骨架与内容分离

「事件不可变」（I1）与「遗忘必须真删」直接冲突。解法是把两者拆到两张表：

| 表 | 内容 | 可变性 | 遗忘时 |
|---|---|---|---|
| `events` | id、时间、类型、隐私、引用 | **禁止 UPDATE/DELETE** | 保留，成为骨架墓碑 |
| `event_payloads` | 加密后的正文密文 + 密钥引用 | 可置空 | 销毁密钥 + 密文置空 |
| `crypto_keys` | 每条/每会话的数据密钥（由主密钥包裹） | 可销毁 | 标记 `destroyed_at`，密钥材料清空 |

效果：**内容不可恢复，但账本完整性可验证**。哈希链（`prev_hash`）证明「曾经有一条这样的事件」，但谁也读不出内容。这比「删行」更诚实，也比「只标删除」更彻底。

> 记忆条目的正文同样需要遗忘，采用相同策略：`memory_entries.content` 在遗忘时置为 `NULL`，并把 `content_hash` 写入 `tombstones`。

## 3. 双时态语义

| 字段 | 含义 | 示例 |
|---|---|---|
| `valid_from` / `valid_to` | 该判断在**用户认知中**成立的区间 | 「9 月到 11 月，我认为方案 B 更好」 |
| `tx_from` / `tx_to` | 系统**记录/修正**该版本的时间 | 「10 月 3 日录入，11 月 20 日被修正」 |

三个必须区分的查询：

| 查询 | 条件 | 用途 |
|---|---|---|
| 当前视图 | `tx_to IS NULL AND status='active'` | 注入、列表 |
| T 时刻认知快照 | `tx_from ≤ T AND (tx_to IS NULL OR tx_to > T)` 且 `valid_from ≤ T AND (valid_to IS NULL OR valid_to > T)` | 「三个月前系统眼中的你」 |
| 演化对比 | 同 `subject+predicate` 的多版本按 `valid_from` 排序 | 「你的看法怎么变的」 |

**禁止**：用 `created_at` 代替 `tx_from`；用 `updated_at` 代替 `valid_to`。两者语义不同，混用会让快照失真（R8）。

## 4. 状态机

### 4.1 记忆条目

```
proposed ──确认──► active ──修正──► (旧行 tx_to 关闭) + 新行 active
   │                 │
   │                 ├──被更强判断取代──► superseded
   │                 └──遗忘──► forgotten（content = NULL）
   └──30 天未确认──► 丢弃（不落库）
```

- 修正**不修改**旧行，只关闭 `tx_to` 并插入新行（`supersedes_id` 指向旧行）。
- 只有 `active` 且 `tx_to IS NULL` 可注入。

### 4.2 候选思想

```
pending ──确认──► confirmed（转 memory_entry）
   ├──编辑──► edited（转 memory_entry，origin=user_confirmed）
   ├──忽略──► ignored
   └──30 天──► expired
```

### 4.3 张力

```
open ──用户处理──► resolved_by_user
  ├──用户否定──► dismissed
  ├──被新判断消解──► auto_resolved
  └──180 天未处理──► stale
```

### 4.4 遗忘作业

```
preview（算影响）──用户确认──► running ──七步──► awaiting_ack ──全部 ack──► done
                                                └──超时──► 条目全局隐藏，仍为 awaiting_ack
```

## 5. 完整 DDL

> 目标方言：SQLite 3.45+，`PRAGMA journal_mode=WAL; foreign_keys=ON;`。
> 扩展：FTS5（trigram）、sqlite-vec（`vec0`）。

### 5.1 事件域

```sql
CREATE TABLE events (
  id           TEXT PRIMARY KEY,                 -- ULID
  device_id    TEXT NOT NULL,
  device_seq   INTEGER NOT NULL,                 -- 设备内单调递增
  lamport      INTEGER NOT NULL,                 -- 跨设备逻辑时钟
  origin       TEXT NOT NULL CHECK (origin IN ('capture','conversation','system','import','sync')),
  kind         TEXT NOT NULL CHECK (kind IN
                 ('note','utterance','judgment','commitment','preference','fact',
                  'decision','correction','forget','confirm','reject','summary','tag','link')),
  actor        TEXT NOT NULL CHECK (actor IN ('user','system')),
  occurred_at  INTEGER NOT NULL,                 -- 事发生时间
  recorded_at  INTEGER NOT NULL,                 -- 本机记录时间
  session_id   TEXT,
  privacy      TEXT NOT NULL DEFAULT 'llm_ok' CHECK (privacy IN ('local_only','llm_ok')),
  refs_json    TEXT NOT NULL DEFAULT '[]',
  payload_state TEXT NOT NULL DEFAULT 'sealed' CHECK (payload_state IN ('sealed','shredded','none')),
  prev_hash    TEXT,
  hash         TEXT NOT NULL,
  UNIQUE (device_id, device_seq)
);

CREATE INDEX idx_events_time   ON events(recorded_at);
CREATE INDEX idx_events_sess   ON events(session_id, recorded_at);
CREATE INDEX idx_events_kind   ON events(kind, recorded_at);

CREATE TABLE event_payloads (
  event_id          TEXT PRIMARY KEY REFERENCES events(id),
  cipher            BLOB,                        -- 遗忘后置 NULL
  nonce             BLOB,
  key_id            TEXT REFERENCES crypto_keys(id),
  plaintext_sha256  TEXT NOT NULL,
  created_at        INTEGER NOT NULL
);

CREATE TABLE crypto_keys (
  id           TEXT PRIMARY KEY,
  wrapped_key  BLOB,                             -- 主密钥包裹后的 DEK；销毁后置 NULL
  scope        TEXT NOT NULL CHECK (scope IN ('event','session','asset','manual')),
  created_at   INTEGER NOT NULL,
  destroyed_at INTEGER
);
```

**触发器（I1 的强制）**：

```sql
CREATE TRIGGER trg_events_no_update BEFORE UPDATE ON events
BEGIN SELECT RAISE(ABORT, 'events are append-only'); END;

CREATE TRIGGER trg_events_no_delete BEFORE DELETE ON events
BEGIN SELECT RAISE(ABORT, 'events are append-only'); END;
```

> 注意：`events.payload_state` 是唯一允许被修改的字段（sealed → shredded），因此触发器需放行该列，或改用 `UPDATE OF payload_state` 白名单。实现时用 `BEFORE UPDATE OF device_id, kind, origin, actor, occurred_at, recorded_at, session_id, privacy, refs_json, hash ON events`。

CREATE TABLE memory_entries (

## 6. 关键视图

### 6.1 可注入视图（把 I2 / I4 / I6 编码进 SQL）

```sql
CREATE VIEW v_injectable AS
SELECT m.*
FROM memory_entries m
WHERE m.status = 'active'
  AND m.tx_to IS NULL
  AND m.fidelity IN ('pass','not_applicable')
  AND EXISTS (
    SELECT 1 FROM evidence e
    WHERE e.subject_type = 'memory' AND e.subject_id = m.id
      AND e.resolver = 'ok'
  )
  AND NOT EXISTS (
    SELECT 1 FROM tombstones t
    WHERE t.target_type = 'memory' AND t.target_id = m.id
  );
```

```sql
CREATE VIEW v_injectable_summary AS
SELECT s.*
FROM conversation_memories s
WHERE s.fidelity_status = 'pass'
  AND s.tainted = 0
  AND EXISTS (
    SELECT 1 FROM evidence e
    WHERE e.subject_type = 'summary' AND e.subject_id = s.id AND e.resolver = 'ok'
  )
  AND NOT EXISTS (
    SELECT 1 FROM tombstones t
    WHERE t.target_type = 'session' AND t.target_id = s.session_id
  );
```

任何注入代码**只能**从 `v_injectable`（记忆条目）与 `v_injectable_summary`（会话摘要）取数，禁止直接查基表。这是 fail-closed 在 SQL 层唯一且必要的强制点。

### 6.2 当前认知视图

```sql
CREATE VIEW v_memory_current AS
SELECT * FROM v_injectable WHERE tx_to IS NULL;
```

### 6.3 T 时刻快照（函数化，参数由应用注入）

```sql
-- 伪 SQL：实际由 query builder 传参
SELECT * FROM memory_entries
WHERE tx_from <= :T AND (tx_to IS NULL OR tx_to > :T)
  AND valid_from <= :T AND (valid_to IS NULL OR valid_to > :T)
  AND status IN ('active','corrected','superseded');
```

### 6.4 可注入 wiki 页视图（I16 / I18 的 SQL 强制点）

```sql
CREATE VIEW v_wiki_active AS
SELECT w.*
FROM wiki_pages w
WHERE w.status = 'active'
  AND json_array_length(w.evidence_json) >= 1
  AND NOT EXISTS (
    SELECT 1 FROM wiki_links l
    WHERE l.src_page_id = w.id AND l.dst_page_id IS NULL
      AND l.weight >= 0.4
  );
```

> 与 `v_injectable` 同理：wiki-first 检索**只能**从 `v_wiki_active` 取数，禁止直接查 `wiki_pages` 基表。stub 链接视为未编译完成，不进入检索（I17）。
> 注意：证据可解析性（`resolver='ok'`）需在应用层二次校验，`evidence_json` 只保证结构存在。

## 7. 字段语义字典

只列容易误用的枚举与字段。

| 字段 | 取值 | 语义 | 误用后果 |
|---|---|---|---|
| `memory_entries.type` | fact / preference / judgment / commitment / relation / event | 决定衰减、冲突规则、是否需证据 | 全部当 fact 会让偏好永不失效 |
| `layer` | L1 / L2 / L3 | 仅决定注入位置与配额 | 当成类型会让冲突规则错乱 |
| `origin` | user_confirmed / user_explicit / system_inferred | 可信度来源 | `system_inferred` 直接 active 违反 I10 |
| `fidelity` | pending / pass / minor_deviation / severe_distortion / not_applicable | 保真度闸门 | 未审即注入违反 I4 |
| `status` | proposed / active / corrected / superseded / forgotten | 生命周期 | `corrected` 仍被注入会回答旧判断 |
| `tx_to` | NULL / 毫秒 | NULL = 当前版本 | 查询忘加 `tx_to IS NULL` 会重复注入多版本 |
| `valid_to` | NULL / 毫秒 | 判断失效时间 | 与 `tx_to` 混用会让快照失真 |
| `origin(events)` | capture / conversation / system / import / sync | 事件来源 | 用于统计与调试，不用于信任判断 |
| `decision` | injected / dropped | 注入结果 | 只记 injected 会让审计看不到「为什么没用」 |
| `reason_code` | 见 05 §4.3 | 丢弃原因 | 缺失则无法解释「它为什么没提这件事」 |
| `resolver` | ok / unresolved / shredded | 证据可解析性 | `shredded` 必须触发级联，否则违反 I2 |
| `payload_state` | sealed / shredded / none | 正文是否可读 | 唯一允许被 UPDATE 的事件字段 |

## 8. 索引与性能预算

| 场景 | 目标 | 依赖索引 |
|---|---|---|
| 当前记忆列表 | ≤30ms / 1000 条 | `idx_mem_current` |
| 单条记忆 + 证据 | ≤20ms | `idx_ev_subject` |
| 会话轮次回放 | ≤50ms / 200 轮 | `idx_turns_sess` |
| 关键词检索 | ≤80ms | `fts_turns` / `fts_memory` |
| 向量 top-20 | ≤60ms / 5 万条 | `vec_memory` |
| 注入回执查询 | ≤10ms | `idx_inj_turn` |
| 遗忘影响预览 | ≤200ms | `idx_refs_mem` |
| 事件增量同步 | ≤100ms / 500 条 | `idx_events_time`、`UNIQUE(device_id,device_seq)` |

容量假设：单用户 3 年 ≈ 20 万事件、5 万条记忆、20 万条证据。超过 100 万事件时启动季度压缩（快照事件 + 冷归档），见 00 R6。

|---|---|---|---|
| I1 | 事件只增 | 数据库 | 触发器 `trg_events_no_update` / `trg_events_no_delete` |
| I2 | active 记忆必有可解析证据 | 数据库 + 应用 | `v_injectable` + 写入前校验 |
| I3 | 注入可追溯 | 应用 | 只从 `v_injectable` 取数；`injection_log.memory_id` NOT NULL 约束（injected 时） |
| I4 | fidelity 未过不进 L2 | 数据库 | `v_injectable` |
| I5 | local_only 不出网 | 应用 | 出口扫描器（06） |
| I6 | forgotten 全视图不可见 | 数据库 | `v_injectable` + 所有列表视图 join `tombstones` |
| I7 | 同区间矛盾必生成张力 | 作业 | `tension_scan` + `pair_hash UNIQUE` |
| I8 | 质询预算 | 应用 + 数据库 | `probe_budget` 原子自增 |
| I9 | LLM 调用必记账 | 应用 | `llm-gateway` 是所有调用的唯一入口 |
| I10 | 系统推断不得直接 active | 数据库 | 触发器：`origin='system_inferred' AND status='active'` → ABORT |
| I11 | 原始音频默认不落盘；开启留存 ≤7 天且可一键清除 | 设备 + 应用 | 设备端策略 + 服务端拒绝超期上传 |
| I12 | 巩固产出不得直接 active | 数据库 + 应用 | 巩固作业只写 `proposed`；复用 I10 触发器 |
| I13 | 旁观者数据不做身份识别 | 应用 | 说话人仅匿名标签；出口扫描拒绝身份字段 |
| I14 | 源文件只读 | 应用 + 评审 | 禁止写源路径；CI 检查 `fs.write` 白名单，命中即失败 |
| I15 | 整理建议必须人确认且可撤销 | 应用 + 数据库 | 只有确认接口能改状态；执行写事件与回执 |
| I16 | wiki 页 active 必有可解析 evidence | 数据库 + 应用 | `v_wiki_active` + 写入前校验 |
| I17 | stub 链接不得静默丢弃 | 应用 | `wiki-linker` 标记 + `wiki-lint` 巡检 |
| I18 | 沉淀产物不得自动 active | 数据库 | 触发器：wiki 页 `created_by='system' AND updated_by IS NULL AND status='active'` → ABORT（人确认写 `updated_by='user'` 后方可 active） |
| I19 | source 与 wiki 同一 embedding 模型/维度 | 应用 | 写入前校验 `settings.embedding_model`，不一致拒绝并记 `compile_runs.errors` |
| I20 | wiki 不替代 source | 应用 | 递归检索必须保留 source 兜底路径 |

I10 触发器示例：

```sql
CREATE TRIGGER trg_no_inferred_active
BEFORE INSERT ON memory_entries
WHEN NEW.status = 'active' AND NEW.origin = 'system_inferred'
BEGIN
  SELECT RAISE(ABORT, 'system_inferred cannot be active without confirmation');
END;
```
