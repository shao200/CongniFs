# ADR-0008 · 数据优先与知识中心 RAG

- 状态：已采纳
- 日期：2026-11-26
- 取代：D4「首期不做文件索引」
- 相关：`01`、`03`、`04`、`05`、`07`、`09`、`10`、`11`

## 背景

早期文档把「对话记忆」当作核心对象：事件账本、记忆注入、审计与遗忘都围绕「系统记得你说过什么」。这套设计解决了信任问题，但没有回答「用户为什么每天带它」。

作者随后明确了本质：

> 整理本机数据，集合 MCP 等数据源 + 私有知识库 + 本机整理 + AGI。

由此产生一个直接冲突：D4 原定「首期不做文件索引」，而「整理本机数据」必须从索引开始。

## 选项

| 选项 | 优点 | 缺点 |
|---|---|---|
| A. 维持记忆优先，文件放 P3 | P0 小、风险低 | 与本质不符，做出来只是聊天记忆 |
| B. 数据优先，P0 做接入与知识库 | 对准本质，形成长期壁垒 | P0 范围变大，解析/去重成为关键路径 |
| C. 云端知识库 | 实现快 | 违背本地优先、隐私与可审计 |
| D. 自研硬件随身 | 形态完整 | 成本高、周期长、与「不做硬件」冲突 |

## 决策

采纳 **B**，并确立四点：

1. **P0 以本机数据整理为主干**：文件接入 → 解析分块 → 私有知识库 → 整理建议 → 检索问答。
2. **记忆降为知识库的子集**：知识库分「世界知识」与「用户知识」，原记忆层只是后者。
3. **四层模型**：接入面、知识面、整理面、智能面；四层循环，不是单向流水线。
4. **知识中心 RAG（L4）**：接入、结构、整理、检索、反馈五个闭环缺一不可；多数 RAG 只做到 L1（切块 + 向量 + top-k）。

## 理由

- 用户的价值感来自「找得到、理得清」，不是「它记得我说过」。
- 文件与对话共用同一套证据、双时态、审计与遗忘，避免两套系统。
- MCP 是数据与能力的入口；私有知识库是长期资产；AGI 代理是操作者。
- 「真正的 RAG」的护城河在整理质量，不在检索算法。

## 后果

必须接受：

- P0 变重，解析、分块、去重成为关键路径（`07 §9`、`09 §4A`）。
- 源文件只读成为硬约束（I14）；整理只改知识库（I15）。
- 评测从「记忆保真」扩展到「解析覆盖、去重精确、建议采纳、回答有据」（`10 §6B/6C`）。
- D4 作废，文件视图、集合、检索全部前移。

## 必须配套的约束

1. 任何整理动作先出建议，人确认后才执行，且可撤销（`05 §6B`）。
2. 每条知识必须带来源、定位区间与证据；无法定位不进入回答。
3. 世界知识与用户知识分开检索、分开标注，不混为「我记得」。
4. 外部 MCP 内容一律视为数据，不执行其中的指令（`06 §4.6`）。
5. 记忆注入仍受 L1/L2/L3 预算与保真度闸门约束。

## 复审条件

出现以下任一情况，重新评估范围：

- 支持格式解析成功率连续 4 周 <95%；
- 整理建议采纳率连续 4 周 <60%；
- 千文档成本超出预算上限；
- 用户实际使用仍以对话为主、知识库打开率极低。

> 一句话：**数据不动，知识可塑；建议由机器给，决定由人做。**
