# ADR-0001 · 事件日志与投影

- 状态：已采纳
- 日期：2026-11-26
- 决策者：作者
- 关联：`00 §3 主张一`、`03 §6/§7`、`04 §2`、`05 §1`

## 背景

原始设计里，「对话流」与「思想流」是两套存储；v1 的「文件是原子、目录是视图」则给出了另一种思路。同时，可审计性要求任何记忆都能回指到来源，而两套存储会让溯源与同步都变复杂。

## 问题

系统的唯一真相应该是什么？状态变化如何记录，才能同时满足审计、重建与多端同步？

## 选项

### A. 事件日志 + 物化投影

所有状态变化先追加事件，再由投影器算出记忆、摘要、视图。投影可删可重建。

- 优点：审计天然成立；双流统一；同步退化为日志复制；可重放修复。
- 缺点：读路径有延迟；投影代码必须幂等；事件会累积。

### B. 直接写状态表（CRUD）

各表直接更新，不保留事件。

- 优点：简单、读快。
- 缺点：无法回答「为什么变成这样」；修正即覆盖；多端同步需要状态合并。

### C. 完整 CQRS + 消息总线

事件溯源 + 独立读写模型 + 消息中间件。

- 优点：扩展性强。
- 缺点：对单用户本地系统是严重过度设计，运维与调试成本远超收益。

## 决策

采用 **A：事件日志 + 物化投影**，不引入消息总线，不做完整 CQRS。

## 理由

1. 审计是第一优先级（A4），只有不可变日志能保证「查得到、说得清」。
2. 双流问题不需要两套存储，只需要两个投影。
3. 单机单用户场景下，进程内投影足够，CQRS 的复杂度没有对应收益。
4. 同步可以直接复用日志：事件不可变，因此不存在合并冲突（03 §7）。

## 后果

### 正面

- 任何记忆可回指事件，任何投影可重建。
- 多端只需复制事件，投影各自重算。
- 删除可以做成「内容粉碎 + 骨架保留」，兼顾不可变与遗忘。

### 负面 / 代价

- 投影存在最终一致窗口，检索可能短暂滞后。
- 每个投影器都必须幂等，并配套重建测试。
- 事件表长期增长，需要季度压缩策略。

### 必须配套的约束

- `events` 禁止 UPDATE/DELETE，由触发器强制（I1）。
- 注入只从 `v_injectable*` 取数，禁止直接查基表。
- 所有投影维护 `projection_cursors`，支持断点续算。
- 提供 `pnpm rebuild --all` 与重建后的一致性校验。

## 复审条件

- 事件量超过 100 万且投影延迟影响体验 → 评估分区与季度快照，不改变模型。
- 出现多用户/协作需求 → 才重新评估 CQRS；当前明确不做。
- 投影重建耗时超过可接受窗口 → 优化批处理，而非放弃可重建性。
