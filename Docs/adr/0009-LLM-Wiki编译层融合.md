## 背景

CongniFs 的文档定位是「知识中心 RAG（L4）：接入、结构、整理、检索、反馈五闭环」（ADR-0008），`00 §12` 也已写入「整理面：分类·去重·合并·关联·摘要·建集合」与「智能面：规划·检索·工具·校验·反思·回滚」。但当前代码只实现到 L1–L2：`db.ts` 仅有 `sources/assets/documents/chunks/ingest_jobs/organize_suggestions` 与 4 字段的 `events` 表，检索仅 FTS5，无向量、无实体/事实/关系、无页面网络、无导航索引、无问答沉淀闭环。

LLM Wiki 范式（Karpathy 提出，业界称「知识编译器」）的核心恰是 CongniFs 缺失的那一层：把理解成本前置到资料导入阶段，编译出结构化、可导航、人类可读的页面网络，以 `index.md` 为语义入口；并把问答结果沉淀为可复用条目。两者不是替代关系——LLM Wiki 缺失的来源可追溯、冲突仲裁、人工确认与错误传播防护，正是 CongniFs 已有的 evidence / 双时态 / fail-closed / 建议+人确认机制。

## 关键事实（证据）

| 来源 | 事实 |
|---|---|
| 代码 `src/db.ts`、`src/queries.ts`、`src/app.ts` | 表结构止于 chunks + FTS5；`events` 仅 id/type/payload_json/created_at，与文档中六原子、双时态、哈希链不在同一层级 |
| 文档 `00 §12`、`ADR-0008` | 已定义整理面与智能面，但未定义「编译产物」这一等对象，也无导航入口与沉淀闭环 |
| 外部实践 | LLM Wiki 三层（Raw / Wiki / Schema）；沉淀判定保守优先，输出标题+摘要使准确率约 75%→88%；wiki 与 source 必须同一 embedding 模型；主要风险为错误传播、信息压缩、长期维护成本 |

## 选项（Wiki 页的形态）

| 选项 | 优点 | 缺点 |
|---|---|---|
| A. 纯投影 | 与「一切皆事件、一切视图皆投影」完全一致，可重建、审计完美 | 人不能直接编辑，丢失 LLM Wiki「人类可读可手工纠错」的核心价值 |
| B. 一等实体 + 事件溯源 | 有版本链与审计，同时允许人直接编辑（编辑写 correction 事件） | 多一套表，投影不能简单重放重建 |
| C. 物化视图 + 人工覆盖层 | 兼顾可重建与可编辑 | 冲突处理复杂，过度设计 |

## 决策

1. 采纳 **B**：wiki 页是一等实体（`wiki_pages` + `wiki_page_versions`），可被人直接编辑，每次编辑写 correction 事件并生成新版本；系统生成产物默认 `proposed`，人确认后 `active`。
2. 编译层作为**独立层**插入「知识面」与「整理面」之间（编译：资料 → 页面/链接/索引），不替换任何现有层；问答沉淀闭环（`qa_distill`）作为 P1 增量。
3. P0 只确立口径与表结构预留，不实现编译器；先补 L2（向量检索）与 L3（实体/事实），避免把编译层建在空底座上。
4. Wiki 与 source 共用同一 embedding 模型与维度，混用即拒绝写入（I19）。

## 理由

- LLM Wiki 的价值不在「生成 Markdown」，而在知识从一次性上下文变为可积累、可审查、可复用的资产；纯投影（A）会让「可审查可纠错」落空。
- CongniFs 已有的 evidence / 双时态 / fail-closed 恰好补上 LLM Wiki 的错误传播短板；融合是双向增强，不是替换。
- 编译层独立成层，符合「加一种视图 = 加一个投影函数，不动存储」的既有原则，也不会让 P0 失控。

## 后果

必须接受：

- `04` 补 5 张表 + 1 个字段；`03` 补编译层与沉淀数据流；`05` 补沉淀协议；`07` 补 wiki-first 递归检索；`10` 补 5 项指标；`11` 补 P1 阶段。详见 `13`。
- 新增不变量 I16–I19。
- 人工审核是持续成本，不是一次性成本；编译器的每一次模型 / prompt 变更都需版本化与回归。

## 必须配套的约束

1. wiki 页 `active` 必须至少有 1 条可解析 evidence（I16）。
2. `[[链接]]` 目标不存在时标记 stub，不得静默丢弃（I17）。
3. 沉淀产物不得自动 `active`（I18，I10 的延伸）。
4. source 与 wiki 同一 embedding 模型 / 维度（I19）。
5. wiki 页不得替代 source：递归检索必须保留 source 兜底。

## 复审条件

- 沉淀采纳率连续 4 周 <60% → 重审沉淀判定阈值，暂停自动沉淀；
- wiki 命中率 <20% → 重审 index / 导航设计；
- 失效链接率 >5% 或 wiki-source 事实一致率 <90% → 冻结编译器版本，回滚近 7 天产物；
- 升级 embedding 模型的成本 > 收益 → wiki 层保留但退出检索路径。

> 一句话：**让大模型做编译器，让人做总编；编译产物可追溯，原始事实永不动。**
