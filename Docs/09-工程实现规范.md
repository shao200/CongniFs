## 0. 原则

| # | 原则 | 具体约束 |
|---|---|---|
| G1 | 契约先行 | `packages/contracts` 是唯一真相，双端只通过生成的 SDK 调用 |
| G2 | 写入只有一条路 | 任何状态变化必须先追加事件，再投影；禁止直接改投影表 |
| G3 | 不可绕过的闸门 | 注入只从 `v_injectable*` 取数；外呼只经 `llm-gateway` |
| G4 | 可重放 | 投影表随时可 `DROP` 重建，重建结果必须一致 |
| G5 | 失败关闭 | 任何不确定都返回「不执行」，并记录原因码 |
| G6 | 单进程、零中间件 | 不引入 Redis / MQ / 独立向量库 |
| G7 | 本地可调试 | 一条命令起服务、一条命令跑评测、日志全在本地 |

**依赖方向（违反即评审不通过）**：

```
web        → contracts, ui
```

- `core` 内使用 `Date.now()` / `Math.random()` / `crypto.randomUUID()`（必须走注入的 `Clock` / `IdGen`，否则测试不可复现）。

## 3. 事件存储实现

### 3.1 追加协议

```ts
// 伪代码：一个事务内完成
await db.transaction(async (tx) => {
  const seq = await tx.nextDeviceSeq(deviceId);
  const event = {
    id: idGen.ulid(), deviceId, deviceSeq: seq,
    lamport: await tx.nextLamport(),
    origin, kind, actor,
    occurredAt, recordedAt: clock.now(),
    sessionId, privacy,
    refsJson, payloadState: 'sealed',
    prevHash, hash: hashEvent({ ...fields, prevHash }),
  };
  await tx.insertEvent(event);
  if (payload) await tx.insertEncryptedPayload(event.id, payload, keyStore);
  await tx.enqueueAfterCommit();      // 投影/打标/嵌入作业
});
```

规则：

- **一个用户动作 = 一个事务**；不应出现「事件写成功、payload 写失败」。
- `device_seq` 必须由数据库原子自增（`UPDATE device_counters ... RETURNING`），不能在内存计数。
- `hash` 覆盖全部不可变字段 + `prev_hash`，用于 I1 的篡改检测。
- 批量同步写入时保持顺序：按 `(lamport, device_id, event_id)` 排序后逐条插入。
- 任何 `UPDATE events` 都会触发数据库 ABORT；应用层不得捕获后重试。

### 3.2 内容加密

- 每条事件生成随机 DEK，AES-256-GCM 加密 payload；DEK 由主密钥包裹后存 `crypto_keys`。
- 主密钥存系统钥匙串；启动时解包到内存，进程退出即释放。
- 遗忘：删除 `event_payloads.cipher` → 销毁 `crypto_keys.wrapped_key` → `events.payload_state='shredded'`。
- **禁止**把明文正文写入日志、错误堆栈、`llm_tasks`。

## 4. 投影实现

### 4.1 投影器约定

```ts
type Projector = {
  name: string;                                   // 对应 projection_cursors.name
  project(event: EventRecord, tx: Tx): Promise<void>;
  rebuild(tx: Tx): Promise<void>;                 // 全量重建
};
```

- `project` 必须是**幂等**的：`INSERT ... ON CONFLICT DO UPDATE`，或先按 `source_event_id` 删除再插入。
- 所有投影写入必须附带 `source_event_id`，便于追溯与局部重建。
- 投影失败不阻塞主流程，但要写作业失败记录。
- 每处理 100 条事件更新一次 `projection_cursors.last_event_id`（同一事务）。

### 4.2 重建

```bash
pnpm rebuild --projector memory
pnpm rebuild --all
```

- `--all` 会清空投影表（保留 `events` / `devices` / `settings` / `crypto_keys`），按事件重放。
- 重建必须在无写入时执行，或在事务快照中执行。
- 重建完成后自动跑 `check:invariants`。

### 4.3 禁止事项

- 禁止在投影里调用 LLM（应投递作业，由 worker 处理）。
- 禁止在投影里读取 `Date.now()`（用事件时间）。
- 禁止跨投影直接读写对方表（通过事件或查询服务）。

## 4A. 接入流水线实现（v0.4 主干）

### 4A.1 组件与作业类型

```
scanner → fetcher → parser → chunker → enricher → indexer
                ↘ 失败 → dead letter（可重放）
reconciler：定期全量对账，修正 scanner 漏项
```

作业类型固定为：`scan`、`parse`、`chunk`、`enrich`、`index`、`reconcile`、`cleanup`。每类独立队列与并发上限，互不阻塞。

### 4A.2 扫描规则

| 项 | 规则 |
|---|---|
| 根 | 只扫 `sources.enabled=1` 的根，不跨根 |
| 忽略 | `.git`、`node_modules`、`__pycache__`、`$RECYCLE.BIN`、`System Volume Information` 及用户自定义 |
| 符号链接 | `realpath` 必须仍在根内，否则跳过并记录 |
| 隐藏文件 | 默认跳过；`.md`/`.txt` 可配置包含 |
| 权限不足 | 跳过并计数，不中断批次 |
| 大小上限 | 单文件默认 100MB，超限标记 `too_large` |
| 稳定判定 | size + mtime 连续 2s 不变才入队，避免写入中解析 |
| 防抖 | watchdog 事件 2s 合并 |
| 全量对账 | 每 30 分钟一次，补齐漏事件 |
| 忽略规则 | 内置 `.git`/`node_modules` 等 + 每来源 `ignore_json`；`PATCH /v1/ingest/sources/:id/ignore` 更新后热重载 watch |

### 4A.3 幂等与状态

- 幂等键：`source_id + locator + sha256`。
- 状态机：`queued → running → ok | failed → dead`；`skipped` 用于不支持/超限。
- 同一键重复入队直接返回已有作业。
- 解析成功、索引失败时只重试 `index`，不重复解析。
- `attempts ≥3` 进死信；死信保留输入摘要与错误码，可手动重放。

### 4A.4 解析沙箱

解析器视为**不可信代码路径**，必须隔离：

| 项 | 约束 |
|---|---|
| 进程 | 独立子进程或 worker 池，崩溃不影响主进程 |
| 超时 | 默认 30s，超时杀进程并记 `timeout` |
| 内存 | 默认 512MB，超限杀进程 |
| 网络 | 完全禁止 |
| 临时目录 | 每次解析独立，结束即删 |
| 宏 | 永不执行 Office 宏；只读内容 |
| 外部实体 | 禁用 XML 外部实体（XXE） |
| 压缩炸弹 | 限制解压比与总大小；PDF 页数、XLSX 单元格数设上限 |
| 路径穿越 | 解包后路径必须落在临时目录内 |

加密文件不尝试破解，标记 `encrypted` 并提示用户。

P0 实现：`.pdf` / `.docx` / `.xlsx` / `.xls` / `.pptx` 在独立 Node 子进程中解析（`--max-old-space-size=512`），默认 30s 超时（`CONGNI_PARSE_TIMEOUT_MS`）、20MB 输出上限（`CONGNI_PARSE_MAX_OUTPUT`），子进程仅继承最小环境变量并禁用 `net` / `dns`；超时记 `PARSE_TIMEOUT`，坏文件或崩溃记 `PARSE_FAILED`。解析器按需动态加载，避免 PDF 解析时载入表格依赖。解析器池化、临时目录隔离与压缩炸弹上限留到 P1。

### 4A.5 检查点与崩溃恢复

- 每个 `source` 记录扫描游标与最后对账时间。
- 每个作业记录阶段与输入哈希；重跑从失败阶段开始。
- `running` 作业带租约，过期自动回到 `queued`。
- 解析产物先写临时表/临时文件，成功后再提交，避免半成品。

### 4A.6 对账

每 30 分钟全量扫描一次：

| 情况 | 动作 |
|---|---|
| 新文件 | 入队 `parse` |
| 哈希变化 | 新版本；旧版本保留，索引切到新版本 |
| 文件消失 | `missing` +1；连续 3 次仍缺失 → `deleted` + tombstone |
| 文件恢复 | 清除 `missing` 计数，恢复索引 |
| 权限变化 | 更新可读性；不可读则标记 `inaccessible` |

对账结束写一条 `reconcile` 作业记录：新增/变更/缺失/恢复数量。漂移 >1% 触发告警。

P0 实现：启动后先跑一次，之后每 30 分钟一次（`CONGNI_RECONCILE_MS` 可调）；串行、单飞、按来源隔离失败。被忽略的已索引资产标 `ignored`，消失的标 `missing`，两者都不再从检索返回。

### 4A.7 背压与资源

- 解析并发 = `min(CPU-1, 4)`；嵌入批量 32。
- 队列高水位（默认 5000）时暂停 watch，只保留对账。
- 索引每 100 块一个事务，失败只回滚该批。
- 单源并发上限 2，避免一个目录拖垮全局。
- UI 必须显示积压数量与预计完成顺序（不承诺时间）。

### 4A.8 清理与生命周期

- 临时文件每日清理；失败作业的临时产物立即删。
- 删除 `source` 级联删除其 `documents`/`chunks`/索引，不触碰源文件。
- 解析失败只保留元数据与错误码，不保留半成品文本。
- 日志禁止写入正文；只写路径哈希、错误码、耗时。

### 4A.9 可观测性

必须暴露的指标：

| 指标 | 用途 |
|---|---|
| `ingest_files_total{state}` | 吞吐与失败率 |
| `ingest_parse_seconds` | 解析 P95 |
| `ingest_queue_depth{type}` | 积压 |
| `ingest_chunks_per_doc` | 分块异常（过大/过小） |
| `ingest_failures_total{code}` | 按错误码定位 |
| `reconcile_drift_ratio` | 对账漂移 |
| `embed_failures_total` | 向量失败 |

告警阈值：失败率 >5%、积压 >1000、漂移 >1%、单文件解析 >60s。

### 4A.10 重建与回填

- 索引可全量重建：从 `documents`/`chunks` 重算 FTS/向量/图。
- 解析器升级时按 `parser_version` 找出旧版本文档，分批重解析。
- 重建写入影子库，完成后原子切换；失败保留旧库。
- 回填必须限速，避免占满 CPU 影响前台检索。

### 4A.11 测试资产

| 类型 | 样本 |
|---|---|
| 正常格式 | 每个支持格式 3 份（短/中/长） |
| 边界 | 空文件、超长单行、超大表格、深层标题 |
| 恶意/异常 | 加密 PDF、损坏 zip、压缩炸弹、路径穿越文件名、XXE |
| 编码 | UTF-8/GBK/UTF-16、混合换行 |
| 去重 | 精确重复、近似重复、同内容不同格式 |
| 对账 | 新增/修改/删除/恢复/权限变化 |

分块结果做快照测试；解析器升级必须附快照差异说明。

### 4A.12 性能预算

| 动作 | 预算 |
|---|---|
| 扫描 1 万文件（热） | ≤60s |
| 解析文本文件 P95 | ≤2s |
| 解析 50 页 PDF P95 | ≤10s |
| 分块单文档 | ≤50ms |
| 索引 1000 块 | ≤5s |
| 常驻内存 | ≤1GB |

## 5. 作业队列

### 5.1 领取

```sql
UPDATE jobs
SET state='running', locked_by=:worker, locked_at=:now, attempts=attempts+1
WHERE id = (
  SELECT id FROM jobs
  WHERE state='queued' AND run_after <= :now
  ORDER BY run_after LIMIT 1
)
RETURNING *;
```

- 单进程内并发上限默认 2（`[jobs] concurrency`）。
- 每种 `kind` 有独立并发限制，摘要任务不得挤占嵌入任务。

### 5.2 重试与死信

| 项 | 规则 |
|---|---|
| 退避 | `min(30s × 2^attempts, 30min)` + 抖动 |
| 次数 | 按 03 §4.4 每类作业的 `max_attempts` |
| 死信 | `state='dead'`，设置页可见，可手动重放 |
| 幂等 | `UNIQUE(kind, idempotency_key)`，重复投递直接忽略 |

### 5.3 进程重启

启动时把所有 `state='running'` 且 `locked_at` 超过 10 分钟的作业重置为 `queued`（视为崩溃遗留）。

## 6. LLM 网关

### 6.1 唯一出口

```ts
interface LlmGateway {
  complete<T>(req: {
    layer: 'T0' | 'T1' | 'T1.5' | 'T2';
    task: string;
    promptVersion: string;
    messages: Message[];
    schema?: ZodType<T>;
    maxOutputTokens?: number;
    traceId: string;
  }): Promise<T>;
}
```

- **所有**模型调用必须经过此接口；CI 用 grep 禁止其它地方出现 `openai` / `anthropic` / `fetch(` 直连。
- 每次调用（含失败）都必须写 `llm_tasks`。
- 输出若声明了 `schema`，必须校验；不通过时允许 1 次「修复提示」重试，再失败即抛错。

### 6.2 超时与重试

| 层 | 超时 | 重试 |
|---|---|---|
| T1（打标） | 20s | 2 次（仅 5xx/超时） |
| T1.5（对话） | 30s | 1 次 |
| T2（摘要/矛盾） | 120s | 2 次 |

4xx 不重试。流式生成一旦开始，不重试（避免重复输出），改为标记 `partial`。

### 6.3 Prompt 版本

- Prompt 以常量形式存放于 `packages/llm/src/prompts/<task>.ts`，导出 `version` 与 `build()`。
- `version = sha256(模板)[0..8]`，写入 `llm_tasks.prompt_version` 与 `evidence.generator`。
- 修改 Prompt 必须提升版本，禁止原地改动。

### 6.4 预算

- 调用前读 `llm_tasks` 当月累计成本；≥80% 记录警告，≥100% 拒绝 T2。
- 拒绝时返回 `BUDGET_EXCEEDED`，由编排层降级。
- 缓存：T1 打标与嵌入按 `input_hash` 命中缓存，命中不重复计费；对话不缓存。

## 7. 隐私网关

- 出网前统一经过 `scanOutbound(payload)`：
  1. 收集 payload 中引用的 `event_id` / `asset_id`，查 `privacy_labels`。
  2. 任一为 `local_only` → 阻断，返回 `PRIVACY_BLOCKED`。
  3. 正则脱敏：手机号、身份证、银行卡、邮箱；路径替换为 `sha256(path)[0..8]`。
- 扫描器必须有单元测试，覆盖：直接命中、间接命中（通过摘要引用）、嵌套 JSON、流式分片。
- **禁止**把 `local_only` 内容写入任何缓存或日志。

## 8. 数据库访问与迁移

| 规则 | 说明 |
|---|---|
| 访问入口 | 只有 `packages/db` 可以 `import` SQLite 驱动 |
| Schema | Drizzle 定义 + 手写 SQL 迁移 |
| 迁移命名 | `NNNN_verb_noun.sql`，只增不改 |
| 迁移执行 | 启动时自动执行；失败即拒绝启动（fail-closed） |
| 事务 | 一个用例一个事务；跨用例不做长事务 |
| 查询 | 注入/列表必须走视图；复杂聚合用原生 SQL 并附注释 |
| 索引 | 新增查询必须用 `EXPLAIN QUERY PLAN` 验证命中索引 |

投影表变更允许 `DROP` + 重建，不走数据迁移；`events` / `memory_entries` 的变更必须走四步迁移（04 §9）。

## 9. 错误处理与日志

### 9.1 错误类型

```ts
class AppError extends Error {
  constructor(
    readonly code: ErrorCode,      // 03 §5.3
    readonly retryable: boolean,
    readonly detail?: unknown,
    readonly cause?: unknown,
  ) { super(code); }
}
```

- 领域层只抛 `AppError`；HTTP 层统一转换为响应。
- 未捕获异常一律 500 + `INTERNAL`，同时写 `trace_id`，**不把堆栈返回前端**。

### 9.2 日志

| 规则 | 说明 |
|---|---|
| 格式 | 单行 JSON |
| 必填 | `ts` `level` `component` `trace_id` `code` `duration_ms` |
| 禁止 | 正文、密钥、token、完整路径、手机号 |
| 保留 | 14 天，按天滚动 |
| 关联 | 一轮对话的 `trace_id = turn_id`；后台作业用 `job_id` |

## 10. 测试策略与 CI

### 10.1 测试分层

| 层 | 工具 | 覆盖 | 要求 |
|---|---|---|---|
| 单元 | Vitest | `core` 纯函数：打分、双时态、裁剪、级联计划 | 覆盖率 ≥80% |
| 集成 | Vitest + 临时 SQLite | 迁移、事件追加、投影幂等、重建一致性 | 每个投影器必须有重建测试 |
| 契约 | Vitest | schema 快照、SDK 生成 diff | 破坏性变更必须显式批准 |
| E2E | Playwright | 双端布局：对话、查账、遗忘、离线 | 桌面 + 移动两个 viewport |
| 金标 | `pnpm eval:golden` | 30 例全量 | 见 10 |
| 混沌 | Vitest + 故障注入 | LLM 超时、DB 锁、证据粉碎、向量丢失 | 每类故障必须有降级断言 |

### 10.2 CI 必过项

```
1. typecheck + lint
2. 单元 + 集成测试
3. 迁移：空库建库 + 上一版本升级
4. 契约冻结检查（schema diff 无 breaking）
5. 禁用模式扫描（见 10.3）
6. 不变量脚本（种子数据）
7. 金标集 smoke（抽 10 例）
8. 解析器 fixtures（正常/损坏/加密/炸弹/路径穿越）
9. 分块快照测试（每格式至少 3 份）
10. 去重金标对（100 对）
11. 对账模拟（新增/修改/删除/恢复）
```

### 10.3 禁用模式扫描

| 模式 | 原因 |
|---|---|
| `FROM memory_entries` / `conversation_memories` 出现在 `core` / `server` | 必须走 `v_injectable*` 或 db 包 |
| `fetch(` / `openai` / `anthropic` 出现在 `llm` 包之外 | 必须经网关 |
| `console.log` 出现在 `apps/server` | 必须用结构化 logger |
| `Date.now()` 出现在 `core` | 必须用注入的 Clock |
| `UPDATE events` / `DELETE FROM events` | 违反 I1 |
| 明文 `content` 出现在日志调用参数 | 泄露风险 |
| `writeFile`/`rename`/`unlink` 出现在 `ingest`/`parser` | 违反 I14（源文件只读） |
| 解析器直接调用 `exec`/`spawn` 外部命令 | 必须走沙箱封装 |

### 10.4 测试数据

- 固定随机种子；`Clock` 与 `IdGen` 在测试中为确定性实现。
- 每个测试用独立临时数据库文件，测后删除。
- 金标集 fixture 与生产数据完全隔离，禁止混用。

## 12. 备份与恢复

### 12.1 备份

```bash
pnpm backup            # 每日自动；手动可随时执行
```

1. `PRAGMA wal_checkpoint(TRUNCATE)`
2. 复制 `congni.db` + `blobs/` 到 `backups/YYYYMMDD-HHmm/`
3. 生成 `manifest.json`（文件哈希 + 事件数 + schema 版本）
4. 整包加密（密钥见 06 §3.1）
5. 保留 7 份（`config.backup_keep`）

### 12.2 恢复

```bash
pnpm restore --from backups/20261120-0300
```

1. 校验 manifest 哈希
2. 还原数据库与 blobs
3. 校验 `events` 哈希链（I1）
4. `pnpm rebuild --all`
5. `pnpm check:invariants`

任一步失败即中止，不覆盖现有数据（先备份当前状态再恢复）。

### 12.3 灾难边界

- 快照之后、故障之前的事件会丢失，除非另一设备已有副本（07 同步）。
- 必须在恢复文档中写明这一点，不做「零丢失」承诺。
