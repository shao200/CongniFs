# 08 · 模型调度与成本控制

> 版本：v0.1　状态：草案　日期：2026-11-26
> 上游：`00-策划预案` v0.2、`03-总体架构与数据流` v0.1、`07-检索与视图引擎` v0.1
> 下游：`09-工程实现规范`、`10-评测与闸门`
> 本文定义「哪个任务用哪层模型、花多少钱、没钱了怎么办」。所有调用都必须落在这张路由表里。

---

## 0. 目标

| 目标 | 标准 |
|---|---|
| 体验不被成本绑架 | 对话主链路始终可用，降级明确告知 |
| 成本可见 | 每一分钱都能归因到任务、模型、轮次 |
| 可替换 | 换供应商不改业务代码，只改配置与 Prompt 版本 |
| 可验证 | 换模型前必须通过金标集，不能凭感觉 |

**不追求**：极限低价、多供应商自动竞价、自建推理集群。

## 1. 四层模型

| 层 | 定位 | 部署 | 延迟预算 | 断网可用 | 典型任务 |
|---|---|---|---|---|---|
| **T0** | 纯本地、零外呼 | 进程内 / ONNX / 本地服务 | ≤500ms | 是 | 混合检索、嵌入、全文索引、语音转写（可选） |
| **T1** | 轻量、批量、可离线 | Ollama 3B 或低价 API | ≤3s | 有本地模型时是 | 打标、实体抽取、查询改写 |
| **T1.5** | 对话主模型 | 云 API | 首字 ≤2.5s | 否（降级到 T1 简化） | 回复生成、质询措辞 |
| **T2** | 旗舰、离线批量 | 旗舰 API | ≤120s | 否 | 会话摘要、矛盾检测、偏好压缩、保真度复核 |

**关键判断**：3B 模型撑不住「检索 + 注入 + 质询 + 生成」的复合任务，对话必须走云端（00 §2 第 9 项）。T1.5 是独立一层，不是 T1 的别名。

数据任务是另一条轴：**解析、分块、去重、索引默认不调用模型**；模型只用于分类、摘要、实体歧义与整理建议。判断标准是：规则或解析器能达到 90% 准确率，就不上模型。

规则：

- 路由表存于 `packages/llm/src/routing.ts`，与配置合并后生效。
- **任何未登记的任务不得调用模型**，网关直接抛 `UNKNOWN_TASK`。
- 同层内换模型只改配置；跨层升降必须走 §7 的验证流程。
- 层为 `—` 表示不调用模型；`parse` / `chunk` / `retrieve` 默认零 token。

### 2.5 数据任务路由原则

| 原则 | 说明 |
|---|---|
| 规则优先 | 解析器、正则、SimHash、FTS 能解决的不上模型 |
| 本地优先 | 分类与摘要先用 3B；质量不达标再升 T1.5 |
| 批量计价 | 按「千文档」设 token 上限，不按单文档放任 |
| 失败隔离 | 单文档失败不重跑整批；批次可续跑 |
| 按集合生成建议 | 整理建议按集合/目录批量生成，不逐文档调用 |
| 超限降级 | 超预算只做规则打标，不做摘要与关联 |

初始预算（以实测校准，不写死承诺）：

- 1000 份文档：分类 + 摘要 ≤5M tokens。
- 实体抽取只处理低置信 10% 的文档。
- 整理建议每 1000 文档 ≤20 次模型调用。

## 3. 降级矩阵

### 3.1 预算触发

| 月累计 | 动作 | 用户可见 |
|---|---|---|
| <80% | 正常 | 无 |
| ≥80% | 警告；T2 切次旗舰；`probe_wording` 改用模板句 | 设置页黄条 |
| ≥100% | **停 T2**；对话降级为 T1 简化模式 | 顶部红条 + 每次回复标注 |
| ≥120% | 停止一切云端调用，纯本地模式 | 明确提示「已进入纯本地模式」 |

T1 简化模式的具体含义：

- 关闭 L2 语义检索，仅用 L1 + 关键词命中；
- 关闭主动质询；
- 回复以「本地材料 + 简短总结」为主，不追求长文；
- 每次回复下方固定显示「当前为省流模式」。

> 00 原文写「100% 停 T2（对话降级到 T1）」。本文沿用该结论，并在 §12 Q1 记录「是否应改为 100% 只停 T2、120% 才降对话」的待评估项。

### 3.2 故障触发

| 故障 | 检测 | 降级 | 恢复 |
|---|---|---|---|
| T1.5 超时（30s） | 网关 | 重试 1 次 → 第二供应商 → T1 简化 | 下次请求自动恢复 |
| T1.5 5xx 连续 3 次 | 熔断器 | 熔断 60s，期间直接走备选 | 半开探测 |
| T2 超时/失败 | 网关 | 作业退避重试，最多 2 次 | 死信可见，可手动重跑 |
| T1 本地模型未运行 | 启动自检 | 改用低价 API（经隐私网关） | 检测到 Ollama 即恢复 |
| T1 与 API 都不可用 | 双失败 | 跳过打标，保留原始事件 | 后续补跑 |
| 嵌入不可用 | 自检 | 仅关键词检索 | 模型加载后重建缺失向量 |

**所有降级必须写 `llm_tasks`**（`status='blocked'|'timeout'|'error'`），否则预算账本失真（对应 I9）。

## 4. 预算闸门

### 4.1 配置

```toml
[budget]
monthly_usd     = 0        # 0 = 未设置
warn_ratio      = 0.8
stop_t2_ratio   = 1.0
local_only_ratio= 1.2
per_turn_usd    = 0.05     # 单轮软上限
per_day_usd     = 0        # 0 = 不限制
```

D7 未拍板前 `monthly_usd=0`，系统只记账不拦截，并在设置页持续提示「未设置预算」。

### 4.2 预留与结算

```
1. 估算 tokens（按 05 §4.1 的估算规则）
2. 预留：budget.reserved += estimate × price
3. 调用
4. 结算：按实际 usage 校正 reserved，写入 llm_tasks
5. 失败也必须释放预留
```

- 单进程内用内存计数 + 启动时从 `llm_tasks` 汇总恢复，避免重启丢失。
- 预留失败（超限）→ 直接返回 `BUDGET_EXCEEDED`，不发起调用。

### 4.3 单轮上限

- 单轮成本超过 `per_turn_usd` → 截断上下文（先砍 L2，再砍历史轮次），不静默继续。
- 截断行为写入注入回执的 `budget` 字段，用户可查。

## 5. 成本核算

### 5.1 计价表

```toml
[pricing."provider:model"]
input_per_mtok  = 0.0
output_per_mtok = 0.0
cached_input_per_mtok = 0.0
```

- 价格只存在于配置，不写死在代码。
- 每次调用按 `input_tokens × input_price + output_tokens × output_price` 计算。
- 缓存命中按 `cached_input_per_mtok`（若有）或 0 计。

### 5.2 Token 计数

| 优先级 | 方法 |
|---|---|
| 1 | 供应商返回的 usage |
| 2 | 与模型匹配的 tokenizer（本地） |
| 3 | 估算：中文按字计、英文按词 ×1.3，四舍五入 |

估算值必须标记 `estimated=true`，并在周报中单独统计估算占比。**估算占比 >30% 视为记账缺陷**。

### 5.3 归因维度

`llm_tasks` 至少支持按以下维度聚合：

- 层（T1/T1.5/T2）
- 模型与供应商
- 任务（task）
- 日期
- 会话 / 轮次（`trace_id`）

## 6. 缓存

### 6.1 可缓存性

| 任务 | 可缓存 | 键 | TTL |
|---|---|---|---|
| `embed` | 是 | `sha256(text)` | 永久（模型变更即失效） |
| `extract_tags` | 是 | `sha256(model+prompt_ver+text)` | 30 天 |
| `extract_entities` | 是 | 同上 | 30 天 |
| `probe_wording` | 是 | `sha256(tension_pair+风格)` | 7 天 |
| `summarize_session` | 是 | `sha256(model+prompt_ver+session_content_hash)` | 永久（内容变则键变） |
| `generate_reply` | **否** | — | — |
| `fidelity_review` | **否** | — | — |

### 6.2 规则

- 缓存表为 `llm_cache`（04 §5.9）。
- 命中直接返回，写 `llm_tasks.cached=1`、成本 0。
- Prompt 版本或模型变更 → 键自动变化，无需手动清缓存。
- **禁止**缓存含 `local_only` 内容的输出到可被其他上下文命中的位置（缓存键含内容哈希，天然隔离，但仍需在写入前经过隐私网关）。

### 6.3 语义缓存（不做）

按语义相似度复用旧回答，会带来「用旧答案回答新问题」的隐蔽错误，且难以审计。**明确不做**。

## 7. 模型切换与 Prompt 演进

### 7.1 切换流程

```
1. 候选模型写入配置（不启用）
2. 跑 10 的金标集（M1/M2/M3/M6）
3. 通过阈值 → 灰度：在数据库副本上跑一周
4. 对比成本与延迟
5. 正式启用，记录 ADR
6. 保留回滚配置 30 天
```

### 7.2 禁止

- 不得为提高某项指标而牺牲 M3（幻觉引用必须 0）。
- 不得在未跑金标集的情况下换模型。
- 不得修改已发布 Prompt 的版本号而不改内容（版本 = 内容哈希）。
- 不得让不同任务共享同一 Prompt 模板又各自改字段。

## 8. 本地模型运行时

| 模型 | 运行方式 | 内存 | 失败表现 |
|---|---|---|---|
| `bge-small-zh-v1.5` | `onnxruntime-node`，进程内 | ~200MB | 检索退化为关键词 |
| `whisper-small` | 可选，本地子进程 | ~1GB | 转写改用系统听写或云端（需放行） |
| Ollama 3B（T1） | 外部本地服务 | ~4GB | 改用低价 API 或跳过打标 |
| OCR | 系统能力 / tesseract | — | 保留原图，标记待处理 |

- 启动自检：逐个探测可用性，结果写 `settings.model_status`。
- 界面展示「本地能力」区块，不可用时给出具体原因与替代方案。
- 本地模型不参与预算计算（无外部成本），但记录耗时。

## 9. 延迟预算

| 环节 | P50 | P95 | 超时动作 |
|---|---|---|---|
| 检索（三路） | 40ms | 120ms | 用已返回的部分结果 |
| 注入裁剪 | 5ms | 15ms | — |
| 首字（T1.5） | 1.2s | 2.5s | 显示「正在思考」+ 可取消 |
| 完整回复 | 6s | 15s | 允许中断，落 `partial` |
| 摘要作业 | 20s | 60s | 后台，不阻塞 |
| 打标作业 | 2s | 6s | 后台，不阻塞 |
| 嵌入（单条） | 30ms | 100ms | 后台 |

**首字超时是体验红线**：超过 2.5s 必须给反馈（骨架屏或流式占位），不允许空白等待。

## 10. 观测与报表

### 10.1 日报（本地生成）

```
日期 · 总成本 · 调用次数 · 缓存命中率 · 失败率
分层：T1 / T1.5 / T2 各自成本与占比
Top 5 昂贵任务
降级事件：次数与原因
估算 token 占比
```

### 10.2 阈值告警（本地）

| 条件 | 动作 |
|---|---|
| 日成本 > 月预算/20 | 设置页提示 |
| 缓存命中率 <30% | 检查键设计 |
| 估算占比 >30% | 接 tokenizer |
| 失败率 >5% | 熔断器状态检查 |
| 单轮成本 > `per_turn_usd` | 记录并附 trace_id |

### 10.3 月度校准

- 按实际账单核对 `llm_tasks` 汇总，偏差 >5% 视为记账缺陷。
- 用真实分布校准 T1/T1.5/T2 的划分（00 §7 要求首月校准）。

## 11. 成本优化顺序

**只允许按以下顺序优化，越靠前越优先**：

1. **先规则**：解析器、正则、SimHash、FTS 能解决的，不调用模型。
2. **缓存**：确定性任务先查缓存。
3. **缩短上下文**：L2 从 20 条降到 10 条，历史轮次截断。
4. **降级低价值任务**：打标用 T1 而非 T2。
5. **批处理**：夜间批量摘要与打标，共享前缀；按集合而非按文档生成建议。
6. **换更小的模型**：仅在金标集通过后。
7. **本地化**：嵌入、检索、分类优先本地。

禁止：

- 为省钱跳过保真度抽检。
- 为省钱把 M3（幻觉引用）相关的证据定位改成抽样。
- 为省钱关闭注入回执。

## 12. 与评测的关系

| 动作 | 必须通过的指标 |
|---|---|
| 换对话模型 | M6 注入相关性 ≥4.0、M3 = 0 |
| 换摘要模型 | 无歪曲率 ≥80%、严重歪曲 0 |
| 换打标模型 | M1 ≥85%、M2 ≥90% |
| 开启缓存 | 抽样 50 条验证输出与未缓存一致 |
| 缩短上下文 | M6 不下降超过 0.2 |

成本下降不得以质量指标下降为代价；两者冲突时，以 10 的硬否决为准。
