## 1. 定位

### 1.1 一句话

> 一个本地优先、可审计的**个人数据整理系统**：把本机文件、应用数据与 MCP 接入的外部数据，解析成私有知识库，再由 AGI 代理持续整理——你随时能查、能改、能忘，且从不改动源文件。

**形态**：只有手机与电脑，不做任何新增硬件。坐在电脑前，电脑就是随身端；拿起手机，手机就是随身端。它不替代手机，只做跨屏幕连续的知识层。

### 1.2 展开成六句

1. **它接得进。** 本机文件、应用数据、MCP 数据源，只读接入，不改源文件。
2. **它理得清。** 分类、去重、关联、建集合，全部以建议形式给出，人确认后生效。
3. **它说得清。** 每条结论都有原文出处，每次回答都能展开「这次依据了什么」。
4. **它肯放手。** 整理只改知识库，不改名、不移动、不删除；遗忘可验证。
5. **它随身。** 电脑与手机共享同一份知识库，换端接着用。
6. **它想得深。** 先规划再检索；一个问题可以多跳，没有证据就明确说没有。

### 1.3 它不是什么（最容易被误解的五件事）

| 误解 | 事实 | 为什么必须澄清 |
|---|---|---|
| 「又一个 AI 笔记软件」 | 不提供编辑器、不做块级双链、不替代 Obsidian | 一旦做编辑器，80% 精力会花在富文本上，记忆层永远做不完 |
| 「ChatGPT 的记忆功能」 | 记忆在本地、可逐条审计、可导出、遗忘可验证 | 云端黑盒记忆正是本产品要反对的形态 |
| 「录屏式数字记忆（Rewind）」 | 不录屏、不截屏；语音只在你显式发起时转写，默认不保留原始录音 | 全量录制的隐私代价与检索噪声都不可接受 |
| 「第二大脑/知识库」 | 不做知识管理方法论与编辑器，只做数据接入、索引、整理建议 | 方法论产品需要社区与模板；本产品卖的是「把本机数据理清楚」 |
| 「AI 助手/陪伴」 | 不做情绪价值、不做人格、不做拟人化 | 违反 A4：关于你的判断必须可审计，拟人化会诱导用户放弃审计 |

---

### 1.4 四层模型

```
接入面  本机文件/媒体 · 本机应用数据 · MCP 外部数据源（只读）
知识面  文档 · 分块 · 实体 · 关系 · 事实 · 集合（私有知识库）
整理面  分类 · 去重 · 合并 · 关联 · 摘要 · 建集合（建议 + 人确认）
智能面  代理：规划 · 检索 · 工具 · 校验 · 反思 · 回滚
```

- **接入**不改源文件，只读、增量、可对账。
- **知识**有实体、关系、时态与证据，不是一堆 chunk。
- **整理**只产出建议，人确认后才改变知识结构。
- **智能**在知识库之上规划与行动，MCP 是手和感官。

这不是窄义的「检索增强生成」，而是**知识中心 RAG（L4）**：接入、结构、整理、检索、反馈五个闭环缺一不可。多数 RAG 只做到「切块 + 向量 + top-k」，那是演示，不是大脑。

> 决策记录见 `adr/0008-数据优先与知识中心RAG`；实现细节见 03/04/07/09。

## 2. 要解决的问题

**问题不是「记不住」，而是「记住的东西不可信、不可查、不可用」。**

| # | 现象 | 现有方案为什么不行 | 本产品的解法 |
|---|---|---|---|
| P1 | 每次对话都从零开始，昨天说过的事今天要重讲 | 模型上下文有窗口，跨会话无状态 | 事件账本 + 结构化摘要 + 分层注入（A1） |
| P2 | AI 记住了我，但我不知道它记了什么、从哪来 | 云端记忆不可见、不可导出，忘记也不彻底 | 记忆档案 + evidence + 双时态 + forget 回执（A4/A5） |
| P3 | 收藏了几千份资料，但只能按文件夹找 | 物理目录是一维的，换视角要复制文件 | 原子 + 投影：同一批文件多维度虚拟目录（P3 阶段） |
| P4 | AI 要么全被动，要么乱插话 | 推送式主动 = 打扰；无主动 = 工具感 | 只在对话中主动，且受质询预算约束（A2） |
| P5 | 想要智能就得把隐私交出去 | 云端方案默认上传全部上下文 | 本地优先 + 敏感网关 + `local_only` 分级（A4 与 D5） |

### 2.1 问题优先级

P1 与 P2 是**首期必须解决**的，缺一个产品就不成立：只有 P1 是「又一个聊天机器人」，只有 P2 是「又一个记忆库」。P3 是第二阶段价值，P4 是体验差异，P5 是长期信任前提。

## 3. 目标用户

### 3.1 首要用户：一个人，就是作者本人

- 单人使用，不做共享、不做协作、不做权限。
- 每天在 PC 前深度工作 4 小时以上，手机随身。
- 有大量判断需要跨时间复用（项目决策、论文方向、技术选型）。
- 对隐私敏感，不接受「全部上云换智能」。

> 这个用户是唯一的验收者。任何「通用用户会喜欢」的功能，如果作者本人不用，就不做。

### 3.2 三个使用镜头

| 镜头 | 场景 | 产品必须做到 |
|---|---|---|
| 桌前 | 长文写作、技术方案、阅读资料 | 全功能台：对话、检索、记忆档案、修正、遗忘 |
| 路上 | 突然冒出的想法、语音备忘、拍一张资料 | 5 秒内完成捕捉，不打断当前动作，可离线 |
| 回顾 | 「我上个月是怎么判断这件事的？」 | 一句话回溯到当时的判断 + 原文 + 日期 |

### 3.3 非目标用户

- 团队 / 企业（无协作、无权限、无审计员角色）。
- 需要知识库模板与社区生态的用户。
- 需要拟人陪伴或心理支持的用户。
- 期望开箱即用、不愿配置的用户（首期必然要配模型与目录）。

## 4. 产品原则（公理的可检验化）

每条公理必须翻译成一条**能被验收的条款**，否则只是口号。

| 原则 | 来自 | 可检验条款 | 违反示例 |
|---|---|---|---|
| 跨会话连续 | A1 | 任意一场对话结束后，下一场对话能看到上一场的结构化记忆；断链即缺陷 | 关掉页面就忘光 |
| 只在对话中主动 | A2 | 除用户开启的定时摘要外，系统不得在无对话场景推送内容 | 早上自动弹「昨日回顾」 |
| 以当前任务为锚 | A3 | 所有联想必须由当前输入触发；无输入不检索、不联想 | 打开 App 就推荐「你可能想看」 |
| 可查可溯源可改可忘 | A4 | 每条记忆三步内可到达原文；修改生成新版本；删除有回执 | 记忆只能看不能改 |
| 一切可撤销 | A5 | 任何写操作（含批量）都可预览影响并撤销；删除保留墓碑 | 一键清空且无法恢复 |
| 记忆不臃肿 | A4 | 注入有硬预算，超出即裁剪；宁可少注入不可超 | 把全部历史都塞进提示词 |
| 错误记忆比没有更危险 | A4 | 保真度未通过的记忆不参与回答 | 用一条记错的偏好回答半年 |
| 物理层不动 | A5 | 系统永不重命名/移动/删除用户文件 | 自动整理文件夹 |

## 5. 核心用户旅程

### J1 · 日常对话

- **触发**：打开 PC 或手机，想就某事展开。
- **路径**：开场只呈现 1 项（未确认候选 > 未解决张力 > 相关摘要）→ 对话 → 回答下方可展开「依据」→ 结束。
- **成功标准**：回答中至少一次正确使用跨会话记忆，且用户能点开看到来源。
- **失败关闭**：证据不可解析时不注入，回答退化为普通对话，**不提示「我记得你说过」**。

### J2 · 随身捕捉

- **触发**：路上冒出一个判断，或看到一份资料。
- **路径**：语音/文字/拍照 → 本地转写或 OCR → 入队 → 联网后回传 → 异步打标 → 出现在思想流。
- **成功标准**：从点开到完成 ≤5 秒；断网不丢。
- **失败关闭**：转写失败保留原始音频并标记「待转写」，不生成猜测文本。

### J3 · 查账（记忆档案）

- **触发**：怀疑系统记错了，或想看看它到底记了什么。
- **路径**：记忆档案 → 按类型/层/时间筛选 → 点开一条 → 看 evidence 原文 → 修正或遗忘。
- **成功标准**：从打开到看到原文 ≤3 次点击；修正后立即生效且旧版本可查。
- **失败关闭**：evidence 打不开的条目显示「证据缺失」并自动禁止注入。

### J4 · 遗忘

- **触发**：某条记忆不该存在。
- **路径**：选中 → 预览影响（将清理几条引用、几台设备）→ 确认 → 回执。
- **成功标准**：回执列出 7 个存储位置的清理结果与备份保留截止日；全端不可见。
- **失败关闭**：有设备未确认时，条目全局强制隐藏并标记「删除中」。

### J5 · 跨时间回溯

- **触发**：「我三个月前怎么看这件事？」
- **路径**：提问 → 系统按 `transaction_time ≤ T 且 valid_time 包含 T` 取快照 → 呈现当时的判断 + 原文 + 日期。
- **成功标准**：能区分「当时这么想」与「现在这么想」，不把两者混为一谈。
- **失败关闭**：无该时点快照时明确说「没有那个时间的记录」，不推测。

### J6 · 冲突质询

- **触发**：当前陈述与历史判断存在实质对立。
- **路径**：回答前插入一次质询 → 用户选「相关 / 不相关 / 已处理」。
- **成功标准**：每场 ≤1 次、全天 ≤3 次；不相关率 ≤50%。
- **失败关闭**：达到预算即不质询，宁可漏掉也不打扰。

### J7 · 低摩擦捕捉与事后回忆（S0）

- **触发**：在电脑上按一下全局热键，或在手机锁屏小组件里说一句；没有打开完整 App。
- **路径**：输入 → 本地转写/识别 → 显著性闸门 → 编码为情景 → 晚上在任一端问「我今天提过什么关于 X」。
- **成功标准**：从想记到记下 ≤2s（PC）/ ≤3s（手机）；说完到可检索 ≤3s（在线）/ ≤1s（本地）。
- **失败关闭**：离线、麦克风被系统占用或权限缺失时，明确提示并把草稿留在本地，不假装已记录。

### J8 · 夜间巩固与晨报（S1）

- **触发**：次日早晨打开任一端。
- **路径**：读取巩固报告 → 「昨晚我把 12 段情景归并为 4 条事实，其中 1 条与你 9 月的判断冲突」→ 可逐条查看变更。
- **成功标准**：报告可审计、可撤回；用户认可比例 ≥75%。
- **失败关闭**：巩固失败不影响已有记忆，报告明确写「昨晚未完成，原因是……」。

### J9 · 跨端接力与旁观者（S0）

- **触发**：手机上写了一半，回到电脑；或在会议中要记录。
- **路径**：换端后会话、草稿、未读自动续上；录制时系统状态栏与应用内明确指示，可一键停止并删除该段。
- **成功标准**：接力无需重复输入；停止录制后不留下原始音频。
- **失败关闭**：手机离线时接力延迟，但草稿不丢；无法删除他人已看到的内容时如实说明。

### J10 · 接入一个目录并看到整理建议（P0）

- **触发**：第一次使用，选择一个本地目录接入。
- **路径**：扫描 → 解析分块 → 写入私有知识库 → 生成整理建议（打标、归类、去重、关联、摘要）→ 用户在收件箱里批量确认。
- **成功标准**：10 分钟内看到第一批建议；任一回答可展开到原文；任一整理动作可撤销。
- **失败关闭**：解析失败的文件标记为「未解析」并列出原因，不阻塞其他文件；源文件零改动。

### 6.2 永久不做

| 不做 | 理由 |
|---|---|
| 多用户、共享空间、权限体系 | 单人产品，权限会污染所有查询与审计语义 |
| 富文本编辑器 / 块级双链 | 与记忆层无关，成本极高 |
| 自动整理物理文件 | 违反 A5，物理层永不动 |
| 人格画像 / 情绪陪伴 / 拟人化人格 | 违反 A4，拟人化会诱导用户放弃审计 |
| 全量录屏 / 后台截屏 | 隐私代价与噪声不可接受 |
| 云端托管 SaaS / 多租户 | 与本地优先承诺冲突 |
| 任何形式的行为遥测上传 | 行为信号永不出本机 |
| 替代手机的独立通讯设备 | 没有胜算；只做跨屏幕连续的记忆层，手机就是手机 |
| 任何新增硬件（挂坠/眼镜/耳机/工牌） | 手机与电脑已覆盖全部随身场景，不做硬件 |
| 公开网页抓取 / RSS / 搜索引擎结果 | 数据源限定为本机与 MCP，不做公开抓取 |
| 常开摄像头 / 人脸识别 | 社会成本与法律风险远高于收益，不做 |

### 6.3 需要显式开启的能力（默认值）

| 能力 | 默认 | 说明 |
|---|---|---|
| 记忆注入 | 开 | 产品核心，关闭等于退化为普通聊天 |
| 主动质询 | 开（有预算） | 不相关率超阈值自动收紧 |
| 过去卡片 | 关 | 主动开启后生效，避免「被系统评判」的不适 |
| 定时摘要 | 关 | 开启后也只推未解决张力，不做随机联想 |
| 跨设备同步 | 开（局域网） | 可关，关闭后手机退化为纯捕捉 |
| 模型调用上云 | 开 | 可按目录/条目降级为 `local_only`，此时不调用云端 |

## 7. 参照系与差异

| 产品 | 它擅长 | 它缺的 | 我们的差异 |
|---|---|---|---|
| Obsidian / Logseq | 本地文件、双链、插件生态 | 无记忆、目录物理且一维 | 不碰文件，只做索引与多维投影 |
| ChatGPT Memory | 开箱即用、跨会话 | 云端黑盒、不可审计、忘记不彻底 | 本地、可查、可改、可验证遗忘 |
| Notion AI | 工作区一体化 | 记忆绑定文档，不是「你」 | 以人为单位，不以文档为单位 |
| Rewind | 全量回溯 | 无结构化记忆，隐私重 | 只处理显式输入，不录屏 |
| mem0 / Letta / Zep | 开发者友好的记忆框架 | 无产品形态、无审计 UI、无隐私分级 | 面向终端用户的产品，而非 SDK |
| 各类 RAG 知识库 | 文档问答 | 无跨会话人格记忆、无视图 | 一个索引库同时服务记忆、目录、问答 |

**三条真正的差异**（其余都是实现细节）：

1. **可审计**：不是「我记住了」，而是「我给你看账本」。
2. **双流合一**：对话与思想不是两个系统，是同一事件流的两个投影。
3. **本地优先**：智能可以上云，记忆与行为信号不上云。

## 8. 成功标准

### 8.1 北极星指标

> **每周被正确整理、并在之后被实际找回的知识条数。**

它同时约束了「理得清」（有量）、「理得对」（有人确认）、「用得上」（被实际找回）。

### 8.2 阶段性指标

| 阶段 | 指标 | 目标 |
|---|---|---|
| P0 | 连续 4 周、每周 ≥4 天使用 | 达成 |
| P0 | 每周至少 1 次审计动作（查看/修正/遗忘） | 达成 |
| P0 | 跨会话记忆被正确使用（用户未纠正） | ≥30% 的会话 |
| P1 | 过去卡片主动点击 | ≥3 次/周 |
| P1 | 质询不相关率 | ≤50% |
| P2 | `local_only` 内容外发 | 0 |
| P3 | 万级文件视图切换 | ≤1s |
| S0 | 日均捕捉次数 | ≥3 |
| S0 | 捕捉信噪比（用户认可 ÷ 编码） | ≥60% |
| S0 | 跨端接力成功率 | ≥90% |
| S1 | 巩固质量（报告被认可比例） | ≥75% |
| S1 | 长程一致性（30 天后同一事实） | ≥90% |
| P0 | 索引覆盖率（已索引 ÷ 可索引） | ≥95% |
| P0 | 解析成功率（支持格式） | ≥95% |
| P0 | 去重精确率 | ≥95% |
| P0 | 整理建议采纳率 | ≥60% |
| P0 | 回答有据率（可定位断言） | ≥95% |

### 8.3 反指标（出现即视为产品失败）

| 反指标 | 含义 |
|---|---|
| 用户关闭记忆注入 | 记忆不可信或太吵 |
| 用户关闭质询 | 主动性设计失败 |
| 用户执行「全部遗忘」 | 信任崩塌 |
| 审计视图周打开为 0 | 要么没用，要么不敢看 |
| 用户开始手动复制粘贴上下文 | 连续性没做到 |

### 8.4 与 10 的分工

- 本文的指标衡量**产品是否有人用、是否被信任**。
- `10-评测与闸门` 的指标衡量**系统是否记得对、删得干净**（抽取精确率、归因准确率、幻觉引用率、forget 完整率等）。
- 两套都必须过；产品指标好但质量指标崩，等于用错误记忆骗用户。

## 9. 命名与调性

### 9.1 命名（D6 待定）

- `CongniFs` 适合作**仓库名/内核代号**（认知文件系统），不适合作产品名——「Fs」会把用户预期带到文件管理上。
- 产品名建议短、可读、不含 AI 字样。候选方向：时间/记忆/账本意象。
- 在 D6 拍板前，所有文档统一用「本系统」，代码命名空间用 `congni`。

### 9.2 调性

- **克制**：不谄媚、不感叹、不主动抒情。
- **结论先行**：默认先给判断，再给理由（可由 L3 偏好覆盖）。
- **不假装记得**：不确定时说不确定，没有记录时说没有记录。
- **可反驳**：所有关于用户的陈述都附出处，允许当场推翻。

## 10. 产品层风险

只列产品视角的风险，技术风险见 00 的 R1–R13。

| # | 风险 | 表现 | 应对 |
|---|---|---|---|
| PR1 | 记忆变成负担 | 用户觉得「被监视」 | 记忆档案全透明；过去卡片默认关；可整段删除 |
| PR2 | 审计 UI 没人用 | 功能上线即空转 | 默认极简三屏；每周一封「本周记忆摘要」邮件式卡片（本地生成，非推送） |
| PR3 | 首期功能太少留不住人 | 装完就弃 | P0 就必须有完整闭环（对话+记忆+查账），不做半成品 |
| PR4 | 双端并行导致两边都糙 | 手机体验差 | 功能分档：手机只做捕捉/对话/只读，不做编辑 |
| PR5 | 用户预期是「全能助手」 | 失望 | 首次启动明确说明三条边界：不编辑、不陪伴、不整理文件 |
