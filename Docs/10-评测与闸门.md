## 1. 三层评测体系

| 层 | 时机 | 内容 | 谁执行 | 耗时 |
|---|---|---|---|---|
| L1 自动回归 | 每次提交 / 发版 | 金标集回放 + 不变量脚本 + 契约检查 | CI | 分钟级 |
| L2 人工抽检 | 每周固定一次 | 抽取/归因/注入相关性/保真度 | 作者本人 | 30–60 分钟 |
| L3 阶段闸门 | 阶段退出前 | 连续两周的 L1+L2 数据 | 作者判断 | — |

三层缺一不可：只有 L1 会漏掉「语义上对但用户体验差」，只有 L2 会漏掉回归，只有 L3 会把偶发波动当成结论。

## 2. 金标集

### 2.1 构建原则

1. **先写期望，再看系统**：场景与断言在系统实现之前写定，写完后不因系统表现修改断言。
2. **单人标注，双次盲评**：作者标注两遍，间隔 ≥1 天，不一致的条目重新定义断言。
3. **holdout 隔离**：30 例中固定 6 例仅用于闸门，不参与任何参数调整。
4. **只增不删**：失效场景标记 `deprecated`，不删除，保留历史可比性。
5. **每个失败都回填**：线上发现的真实错误，脱敏后新增为场景。

### 2.2 存储结构

```
Docs/eval/
├─ golden/
│  ├─ A01.yaml … J03.yaml        # 30 个场景
├─ fixtures/
│  ├─ turns/*.jsonl              # 预置对话
│  └─ expected/*.json            # 期望产物
└─ reports/
   └─ 2026-W48.md                # 周报
```

单个场景的结构：

```yaml
id: B02
category: 多轮改主意
title: 先说选 A，三天后改选 B
holdout: false
setup:
  sessions:
    - at: 2026-09-01
      turns: ["方案就用 A 吧", "确认"]
    - at: 2026-09-04
      turns: ["想清楚了，还是 B 更好"]
assert:
  - type: must_extract
    count: 2
    types: [judgment]
  - type: must_be_current
    contains: "B"
  - type: must_keep_history
    contains: "A"
  - type: must_be_as_of
    at: 2026-09-02
    contains: "A"
  - type: no_tension
```

断言类型：

| 类型 | 含义 |
|---|---|
| `must_extract` | 必须抽取指定数量/类型的记忆 |
| `must_not_extract` | 不得抽取（负样本） |
| `must_be_current` | 当前视图应包含某内容 |
| `must_be_as_of` | T 时刻快照应包含某内容 |
| `must_keep_history` | 历史版本必须保留 |
| `must_conflict` / `no_tension` | 是否应产生张力 |
| `must_inject` / `must_not_inject` | 注入集是否命中 |
| `must_forget` | 遗忘后各存储位置必须为空 |
| `must_not_resurrect` | 重放后不得复活 |
| `receipt_contains` | 回执必须包含某字段（如备份保留期） |

### 3.1 测量细则

**M1 抽取精确率**

- 抽样框：本周所有 `memory_entries`（不含 `system_inferred`）。
- 判定：该条是否真实反映用户表达（是/否），不看措辞是否优美。
- 置信区间提示：50 样本在 85% 附近约 ±10%，因此**连续两周不达标**才判定失败，单周波动不作为结论。

**M2 归因准确率**

- 自动部分：`evidence.quote` 是否为 `source` 文本子串，且 `char_start/end` 正确。
- 人工部分：源轮次是否确实是「用户说的」（而非助手说的）。
- 任一不满足即算错误。

**M3 幻觉引用率**

- 全量自动：每次写入 evidence 时执行定位，失败即 `resolver='unresolved'`。
- 另设离线审计：遍历全部 evidence 重新定位，防止源文本被后续修改导致漂移。
- **分母是全部 quote，不是抽样**。1 条编造即触发硬否决。

**M4/M5 冲突**

- 金标集固定 6 个冲突场景（H01–H03 + B03 + C02 + J02 中的冲突分支）。
- 每次回归输出混淆矩阵：TP / FP / FN。
- 召回率低说明漏报（用户被错误记忆影响），精确率低说明误报（打扰）。

**M6 注入相关性**

- 盲评：只看「问题 + 回复 + 注入列表」，不看打分与排序。
- 1 分=完全无关/误导，5 分=没有它回答会明显变差。
- 若一轮注入 0 条，不参与评分，但计入「空注入率」观察项。

**M7 forget 完整率**

- 七步检查：`memory_entries` / `memory_refs` / 向量 / FTS / `edges` / `tombstones` / 跨端 ack。
- 自动脚本对每次 `forget_jobs` 执行；任一步 false 即失败。
- 每月人工复核 3 份回执，确认文案与实际一致（尤其备份披露）。

**M8 成本**

- 按 `llm_tasks` 聚合，分层统计 T1/T1.5/T2。
- 与 08 的预算表对照；超 80% 预警，100% 触发降级（不是评测失败，但必须记录）。

## 4. 保真度闸门（操作化）

### 4.1 抽样

| 来源 | 数量 | 说明 |
|---|---|---|
| 随机 | 每周 10 条 | 覆盖所有生成器 |
| 低置信 | 全部 `confidence < 0.6` | 高风险条目必查 |
| 高频 | 被注入 ≥3 次的条目 | 影响面大优先查 |
| 新生成器 | 上线首周 20 条 | 版本切换必查 |

### 4.2 判定流程

1. 只看「记忆条目 + evidence 原文」，不看系统其它输出。
2. 三选一：忠实 / 轻度偏差 / 严重歪曲。
3. 严重歪曲必须选四类之一：`not_said` / `polarity` / `misattribution` / `fabricated_detail`。
4. 判定结果写 `fidelity_reviews`，同时更新该条 `fidelity`。

### 4.3 周口径

```
无歪曲率 = (忠实 + 轻度偏差) ÷ 已判定条数
严重歪曲数 = count(severe_distortion)
```

### 4.4 触发后果

| 情况 | 动作 |
|---|---|
| 单条严重歪曲 | 该条 `corrected` + 禁止注入（05 §5.3） |
| 同一生成器累计 2 次 | 冻结该 `model@prompt_hash`，回滚上一版本，重跑近 7 天摘要 |
| 周无歪曲率 <80% | 暂停新增记忆注入，只保留已通过条目；进入修复 |
| 严重歪曲 >0 | **硬否决**：停止发版，直到定位并回滚 |

## 5. 遗忘验证协议

### 5.1 自动检查（每次遗忘）

```sql
-- 示例：检查记忆是否真的从可注入面消失
SELECT COUNT(*) FROM v_injectable WHERE id = :memory_id;      -- 期望 0
SELECT COUNT(*) FROM vec_memory  WHERE memory_id = :memory_id; -- 期望 0
SELECT COUNT(*) FROM fts_memory  WHERE rowid = :rowid;         -- 期望 0
SELECT COUNT(*) FROM edges
 WHERE (src_id = :memory_id OR dst_id = :memory_id);           -- 期望 0
```

七步状态全部为 true 才计为通过；跨端未 ack 不计失败，但必须出现在回执中。

### 5.2 人工复核（每月 3 份）

- 回执中的「影响条数」是否与预览一致。
- 备份披露日期是否真实（对照备份目录）。
- 是否出现「已彻底删除」等过度承诺措辞。

### 5.3 硬否决

`forget 完整率 < 100%` 或「回执与事实不符」→ 立即停止发版，优先于任何功能。

## 6. 阶段闸门

### 6.1 判定窗口

- 每个阶段退出前，必须有**连续两周**满足条件的数据。
- 单周达标不算通过；两周中任一周硬否决即不通过。
- 数据不足（如 M1 样本 <30）时，延长一周，不用小样本下结论。

### 6.6 判定流程

```
收集两周数据 → 自动报告 → 人工复核异常项
   → 全部达标：进入下一阶段
   → 任一硬否决：停止，回滚，修复后重新计时
   → 非硬指标未达标：修复后延长一周复测
```

决策人只有作者一人，但**必须留下书面记录**（周报 + 结论 + 依据），否则视为未通过。

## 7. 阈值校准

### 7.1 初值与来源

| 参数 | 初值 | 来源 | 校准方式 | 复审时点 |

### 7.2 校准规则

1. 每次只调**一个**参数。
2. 调整前后各跑一次完整金标集，记录差值。
3. 调整写入周报，并链接到对应 ADR。
4. holdout 6 例**永远不参与**校准，只在闸门时跑。
5. 参数调整不得为了让本周达标而做；必须解释机制原因。

## 9. 防自欺清单

| 风险 | 具体表现 | 约束 |
|---|---|---|
| 用系统输出当标注 | 看它抽了什么，再决定「这算对」 | 标注时只看原文，不看抽取结果 |
| 改断言迁就实现 | 结果不对就放宽断言 | 断言改动需单独提交并写明理由 |
| 小样本下结论 | 10 条里 8 条对就宣布 80% | 规定最小样本量与连续两周 |
| 只测 happy path | 全是「用户明确说记住」 | 金标集必须含 3 个负样本（A03 等） |
| 遗忘只测数据库 | 向量/FTS/边没查 | 七步脚本强制 |
| 冲突只测能检出的 | 不统计漏报 | 必须同时报召回与精确 |
| 成本不记账 | 只统计成功调用 | `llm_tasks` 记录 error/timeout/blocked |
