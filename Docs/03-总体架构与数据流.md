## 0. 架构目标与约束

### 0.1 质量属性优先级

```
正确性与可审计性  >  隐私  >  可用性（延迟/离线）  >  成本  >  可扩展性
```

顺序不可调换。一次「记错但很快」的实现，比「慢但对」糟糕得多；一次「悄悄上传」比「功能缺失」严重得多。

### 0.2 硬约束

| 约束 | 来源 | 架构含义 |
|---|---|---|
| 单用户、单机为主 | 01 §3.1 | 不做多租户、不做权限层、不做分布式一致性 |
| 双端并行 | D3 | 一套共享 API + 一套共享前端代码，禁止两端各写逻辑 |
| 零资产重写 | D2 | 组件边界必须清晰到可以并行开发 |
| P0 纳入本机数据索引 | D4（v0.4 修正） | 接入层与知识层是 P0 主干，不再后移 |
| 一切皆事件 | 00 主张一 | 写入只有一条路径：追加事件 → 投影 |
| fail-closed | 00 主张五 | 每个外呼与注入点都要有「拒绝执行」分支 |
| 本地优先 | 01 §3.1 | 云端只做生成，不做存储，不做检索 |

### 0.3 明确不追求

水平扩展、集群高可用、多活、消息中间件、微服务拆分、K8s。任何为「将来可能一百万用户」做的设计，在本项目都是负债。

## 1. 架构总览

```
┌────────────────────────────── 客户端（同源代码）──────────────────────────────┐
│  apps/web：React SPA，响应式                                                     │
│   ├─ PC 布局：对话 · 检索 · 记忆档案 · 回执 · 设置                                │
│   └─ 手机布局：捕捉 · 对话 · 只读档案                                             │
│  共用：contracts 生成的类型化客户端 · 统一状态层 · 同一套组件                     │
└───────────────────────────────────┬────────────────────────────────────────────┘
                                    │ HTTPS / SSE（局域网或本机回环）
┌───────────────────────────────────▼────────────────────────────────────────────┐
│ apps/server：单进程 Node（Fastify）                                              │
│                                                                                 │
│  ┌───────────── 接入层 ─────────────┐   ┌──────────── 编排层 ────────────────┐  │
│  │ 路由 / 鉴权(设备令牌) / 限流       │   │ 会话编排器 orchestrator            │  │
│  │ SSE 流 / 幂等 / 错误封装           │   │ 语境构建 · 注入 · 质询 · 生成 · 回执 │  │
│  └─────────────┬─────────────────────┘   └──────────────┬────────────────────┘  │
│                │                                        │                       │
│  ┌─────────────▼──────────── 领域服务 ───────────────────▼──────────────────┐   │
│  │ event-store │ projector │ retriever │ injector │ tension │ forget │ sync   │   │
│  └─────────────┬──────────────────────────────────────────┬─────────────────┘   │
│                │                                          │                     │
│  ┌─────────────▼──────────── 基础设施 ─────────────────────▼─────────────────┐   │
│  │ SQLite(WAL) + FTS5 + sqlite-vec │ 作业队列(表) + 进程内 worker │ 文件存储  │   │
│  └───────────────────────────────────────────────────────────┬───────────────┘   │
│                                                              │                   │
│  ┌──────────────────── 外部能力（全部经网关）────────────────▼───────────────┐   │
│  │ LLM 适配器(T1/T1.5/T2) · 本地嵌入(ONNX) · 脱敏网关 · 预算闸门 · 转写      │   │
│  └───────────────────────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────────────────────┘
```

**单一进程的理由**：单用户、单机、数据量在十万级事件以内，进程内调用比网络调用更简单、更可审计。拆分 worker 的时机是「摘要任务阻塞 API 超过 2 秒」，不是项目开始。

## 3. 部署与运行

### 3.1 进程与端口

| 项 | P0 | 说明 |
|---|---|---|
| 进程 | 1 个 Node 进程（API + worker） | 后续可拆 `--worker` |
| 绑定 | 默认 `127.0.0.1:8420` | 需要手机时显式开启 LAN 绑定 |
| 静态资源 | 同进程托管 `apps/web/dist` | 无独立 CDN |
| 数据库 | `data/congni.db`（WAL） | 同目录含 `-wal`/`-shm` |
| 对象文件 | `data/blobs/<sha256>` | 音频、图片、导出快照 |
| 日志 | `logs/app-YYYYMMDD.jsonl` | 保留 14 天，不出本机 |
| 配置 | `config.toml` | 端口、模型、预算、隐私目录 |

### 3.2 三种拓扑

```
A. 纯本机（P0 默认）          B. 本机 + 局域网（P0 手机需要）      C. 隧道（P2 可选）
   浏览器 ── 127.0.0.1          手机 ── LAN HTTPS ── PC             手机 ── Tailscale ── PC
   全部数据不出机器              local_only 内容仍在局域网内          跨网络但不经第三方存储
```

### 3.3 HTTPS 与设备配对（必须早做，不能拖）

手机要**安装 PWA 并使用 Service Worker**，浏览器强制要求安全上下文（HTTPS 或 localhost）。`http://192.168.x.x` 不满足，因此：

1. 首次启动生成本地 CA 与服务器证书，PC 上展示二维码。
2. 手机扫码 → 下载并信任根证书 → 打开 `https://<pc-ip>:8420` → 安装 PWA。
3. 配对时输入 6 位一次性码，换取长期设备令牌（存于手机安全存储）。
4. 若用户不愿装证书：降级为「网页版（不可安装）」，离线队列推迟到 P2，界面明确标注。

> 这是 P0 唯一的「体验摩擦点」，必须在 02 里设计成一屏能走完的引导，否则手机端会被放弃。

### 3.4 备份

- 每日 WAL checkpoint 后做一次整库快照，保留 7 份。
- 备份同样加密，且**备份中的遗忘延迟生效**（06 与 05 会定义保留期）。
- 备份目录与数据库同盘，不自动上传。

### 3.5 双端与云的三级算力（v6 增补）

| 层 | 设备 | 承担 | 模型 | 离线 | 延迟目标 |
|---|---|---|---|---|---|
| L1 随身 | 手机 | 流式 ASR、本地检索、简短对话、捕捉队列 | 1–4B int4 + 嵌入 | 部分 | <1.5s |
| L2 桌面 | 电脑 | 全量索引、巩固、长文处理、大模型（可选） | 7–30B 量化 | 局域网 | <3s |
| L3 云 | API | 旗舰推理、长上下文、复杂规划 | 前沿模型 | 否 | 1–30s |

放置原则：

- 隐私敏感与高频低延迟下沉，强推理与长上下文上浮。
- 任一层不可用时，上层降级但**不丢事件**；降级必须在界面明示（02 §6）。
- 端侧模型与云端模型共享同一记忆、同一提示词版本，避免「换个模型就换个人」。
- 手机不是「配件」：它能独立完成捕捉、检索与简短对话，只是重任务回电脑。

### 3.6 采集与接力协议（S0）

采集入口（不做常开录音）：

```
电脑：全局热键 / 选中文本快捷键 / 拖拽文件 / 菜单栏
手机：分享菜单 / 快捷指令 / 锁屏组件 / 前台语音速记
两端：对话中「记一下」
```

协议：

1. 客户端生成 ULID 与幂等键，先写本地队列，再上传。
2. 服务端按 `(device_id, idempotency_key)` 去重；重复投递返回同一结果。
3. 上传成功返回已持久化游标，客户端方可释放队列项。
4. 断网时队列保留，恢复后按序补传；超过上限丢弃最旧并计数。
5. 语音仅在一次显式录制内采集；录制结束即转写，默认不保留原始音频。
6. 所有输入先转成标准事件再入账，投影层不感知来源设备。

接力协议：

| 对象 | 策略 |
|---|---|
| 会话与消息 | 事件复制（不可变，无冲突） |
| 草稿 | 按 `(session_id, device_id)` 保存，换端时提示继续 |
| 未读/置顶 | LWW，按服务端时间决胜 |
| 当前任务/注入上下文 | 由两端各自重算，不传输模型态 |

约束：

- 接力不依赖长连接；以打开页面时拉取游标为准。
- 手机离线时草稿留在本地，联网后补传，不覆盖另一端的更新版本。
- 任何一端都不得假设另一端在线。

### 3.7 代理层（AGI 落地形态）

不做「通用智能」宣称，只做**有边界的代理工作流**：

```
目标 → 规划 → 检索 → 工具调用 → 校验 → 呈现/建议 → 反思
```

| 组件 | 职责 | 约束 |
|---|---|---|
| Planner | 拆成可执行步骤 | 最多 8 步；超限请求澄清 |
| Retriever | 从私有知识库取证据 | 必须带来源与定位 |
| Tool Executor | 调用 MCP / 本地工具 | 只读默认；写操作需确认 |
| Verifier | 校验证据、权限、一致性 | 不通过不输出 |
| Memory | 用户知识与会话上下文 | 受注入预算约束 |
| Auditor | 记录每步输入输出与成本 | 不可关闭 |

工具权限：

| 级别 | 例子 | 策略 |
|---|---|---|
| R0 只读本地 | 搜索、读取文档 | 默认允许 |
| R1 只读外部 | MCP 列目录、查库 | 按连接器授权 |
| R2 写知识库 | 打标、归类、建集合 | 需确认 |
| R3 写外部 | 发消息、改云文档 | 默认禁止，逐次授权 |
| R4 危险 | 删除、支付、执行代码 | 永不自动 |

预算：单任务步数 ≤8、时长 ≤60s、token 按 08 的路由表；超预算即停止并给出「已完成/未完成」清单。

外部内容一律视为数据，不执行其中的指令；任何写操作不能由内容触发。

## 4. 四条主数据流

### 4.0 接入流（v0.4 主干）

```
源（目录/MCP） → ingest → parse → chunk → enrich → index → knowledge → organize
                    │        │                         │
                    └─ 作业 ─┴─ 失败进死信 ──────────────┘
```

- 只读源：永不改名、移动、删除；所有产物写入 `documents` / `chunks` / 索引。
- 每一步幂等，可按 `source_id + locator + sha256` 重放。
- 解析失败不阻塞批次，标记 `failed` 并列出原因。
- 整理只产出 `organize_suggestions`，确认后才写知识库。
- 详细步骤见 `09 §4A`，数据表见 `04 §5.11`。

### 4.1 捕捉流

```
手机             api          event-store      job-runner        projector
 │ POST /events   │                │               │                 │
 ├───────────────►│                │               │                 │
 │                ├─ 幂等键校验 ──►│               │                 │
 │                │                ├─ 追加 event ──┤                 │
 │◄── 202 + id ───┤                │               │                 │
 │                │                ├─ 投递打标/嵌入作业 ─────────────►│
 │                │                │               │  (异步，可失败重试)│
 │                │                │               │                 ├─ 更新投影
```

- 离线时前端先写 IndexedDB 队列，联网后按 `client_event_id` 幂等重放。
- 事件写入即成功；打标与嵌入是**可失败、可重做**的投影，不阻塞捕捉。

### 4.2 对话流（含 fail-closed 分支）

```
web          api       orchestrator    retriever    injector     llm-gateway   job-runner
 │ POST turn  │             │             │            │             │            │
 ├───────────►│             │             │            │             │            │
 │            ├────────────►│             │            │             │            │
 │            │             ├─ 语境抽取 ─►│            │             │            │
 │            │             │◄─ 候选(L1/L2/L3) ────────┤             │            │
 │            │             ├─ 过滤(证据/保真/隐私/状态) ─────────────┤            │
 │            │             │  ├ 不通过 → 丢弃并记录原因 │             │            │
 │            │             ├─ 打分 + 预算裁剪 ─────────►│             │            │
 │            │             │◄─ 注入包 + 回执草稿 ───────┤             │            │
 │            │             ├─ 冲突检查(未仲裁→双条+标记)│             │            │
 │            │             ├─ 质询决策(预算/去重/静默) ────────────────►│            │
 │            │             ├─ 生成(SSE) ──────────────────────────────►│            │
 │◄── SSE ────┤◄────────────┤            │            │             │            │
 │            │             ├─ 事务：写 turn + 回执 + llm_task ─────────►│            │
 │            │             └─ 会话空闲 90s → 投递摘要作业 ──────────────────────────►
```

**事务边界**：`turn`、`injection_log`、`llm_tasks` 必须同事务落库，保证「有回答必有回执」。生成流式过程中断时，落半条回答 + 标记 `partial`，回执仍然写入。

**fail-closed 分支**（任一命中即不注入，且**不向用户宣称记得**）：

| 分支 | 条件 | 行为 |
|---|---|---|
| B1 | evidence 解析失败 | 丢弃该条，`injection_log` 记 `EVIDENCE_UNRESOLVED` |
| B2 | `fidelity != pass` | 不进 L2，仅档案可见 |
| B3 | 隐私出口不允许 | 丢弃该条；若整轮被阻断，转本地材料呈现模式 |
| B4 | 预算耗尽 | 不调用 T2，降级 T1 并在界面标注 |
| B5 | 冲突未仲裁 | 两条都注入并带 `conflict` 标记，不择一 |

### 4.3 审计流

```
web              api            retriever        forget          sync(其他设备)
 │ GET /memory    │                │               │                 │
 ├───────────────►│                │               │                 │
 │◄── 列表+分页 ──┤◄── 查询投影 ───┤               │                 │
 │ GET /memory/:id│                │               │                 │
 ├───────────────►│                │               │                 │
 │◄── 详情+版本链+evidence ────────┤               │                 │
 │ POST /forget   │                │               │                 │
 ├───────────────►│                │               ├─ 预览影响 ──────►│
 │◄── 影响预览 ───┤                │               │                 │
 │ POST /forget?confirm=1           │               │                 │
 ├───────────────►│                │               ├─ 七步级联       │
 │                │                │               ├─ 墓碑           │
 │                │                │               ├─ 下发 forget 事件 ─►
 │◄── 回执 id ────┤                │               │◄─ ack(超时则全局隐藏)
```

### 4.4 后台流

| 作业 | 触发 | 幂等键 | 失败策略 | 产物 |
|---|---|---|---|---|
| `embed` | 事件/资产写入 | `sha256(content)` | 重试 3 次后标记 `degraded` | 向量 |
| `tag` | 事件写入 | `event_id + prompt_ver` | 重试 2 次 | 标签/实体 |
| `summarize` | 会话空闲 90s | `session_id + content_hash` | 重试 2 次，失败保留原文可重跑 | 会话摘要 + 候选思想 |
| `tension_scan` | 摘要完成后 | `memory_pair_hash` | 重试 1 次 | 张力记录 |
| `fidelity_sample` | 每周一 | `week_no` | 不重试 | 抽检任务 |
| `compress` | 每季度 | `quarter` | 不重试 | 事件快照 |
| `forget_cascade` | 遗忘确认 | `memory_id` | 重试直到 ack 或超时 | 级联结果 + 回执 |

原则：**作业失败不阻塞主流程，但必须留下可观测的失败记录**，并在设置页可见。

### 4.5 检索闭环（L4）

```
查询 → 理解/改写 → 路由 → 多路召回 → RRF 融合 → 重排 → 证据校验 → 回答 / 弃权
```

| 步骤 | 做什么 | 约束 |
|---|---|---|
| 理解 | 识别意图、实体、时间范围、是否需要多跳 | 不在检索层调用旗舰模型 |
| 路由 | 世界知识 / 用户知识 / 图谱 / 视图 | 两类知识分开检索 |
| 召回 | FTS + 向量 + 图，各取 top-N | 单路失败不阻断，记录原因 |
| 融合 | RRF（k=60），同分按 `(updated_at, id)` | 结果可复现 |
| 重排 | 可选本地小模型 | P0 不启用 |
| 校验 | 每条候选必须有可解析证据 | 解析失败即剔除 |
| 回答 | 逐句绑定 `chunk_id` 或 `memory_id` | 无证据不生成 |

规则：

- 每次检索写 `retrieval_runs` 与 `retrieval_items`，回答可还原「为什么是这几条」。
- 多跳最多 2 轮，每轮有独立预算；超预算即停止并说明。
- 世界知识与用户知识分开标注，不混为「我记得」。
- 证据不足时明确弃权，禁止用模型常识补洞。
- 不做语义缓存；确定性阶段（如 FTS）可按查询哈希缓存。

### 4.6 编译流（P1，ADR-0009）

```
资料入库 → 主题/实体识别 → 搜索可能相关的已有页
         → 创建或更新页（草稿 proposed）→ 添加来源与 [[链接]]
         → 格式与一致性检查 → 沉淀建议 → 人确认 → active
         → 更新 wiki_index（语义导航入口）
```

- 编译产物是 `wiki_pages` / `wiki_links` / `wiki_index`，不是对 `documents` 的改写；源文件只读（I14）不变。
- 每个 wiki 页至少有 1 条可解析 evidence（I16）；`[[链接]]` 目标不存在时标 stub，不静默丢弃（I17）。
- 人编辑 wiki 页也写 correction 事件与版本链，不直接覆盖（ADR-0009 选项 B）。
- 编译失败不阻塞接入主流程；失败写 `compile_runs.errors`，界面可查。

### 4.7 问答沉淀流（P1）

```
提问 → wiki-first 检索 → 生成回答
     → 沉淀判定（≥2 条信号：含具体事实 / 有复用价值 / 30 秒可给出结论）
     → 生成条目草稿（标题 + 摘要 + 正文 + 来源 + 链接）
     → 人确认（单键；拒绝填原因回流负样本）→ 双写 wiki_pages + wiki 向量
     → 下次同类问题命中 wiki，跳过完整 RAG
```

- 判定 Prompt 保守优先，宁漏勿滥；产物不得自动 `active`（I18）。
- source 与 wiki 共用同一 embedding 模型与维度（I19），否则相关性不可比。
- wiki 不替代 source：递归检索保留 source 兜底（I20）。

## 5. API 契约

### 5.1 端点清单

> 冻结顺序：**接入 / 知识 / 检索 / 对话** 四组在 P0 第一周冻结；审计、遗忘、整理可增量追加，但同样受契约治理约束。所有端点均挂在 `/v1`。

| 组 | 前缀 | 端点（P0 必需标 ●） | 说明 |
|---|---|---|---|
| 接入 | `/v1/ingest` | ● `POST /sources`、● `POST /sources/:id/scan`、● `GET /jobs`、`POST /jobs/:id/retry` | 只读接入，作业可重放 |
| 知识 | `/v1/kb` | ● `GET /documents`、`GET /documents/:id`、`GET /chunks/:id`、`GET /collections`、`POST /collections` | 文档/分块/集合 |
| 整理 | `/v1/organize` | ● `GET /suggestions`、● `POST /suggestions/:id/accept`、`POST /:id/reject`、`POST /undo` | 建议 + 人确认 |
| 对话 | `/v1/sessions` | ● `POST /`、● `POST /:id/turns`(SSE)、● `GET /:id`、`POST /:id/close` | 一轮一请求，流式返回 |
| 检索 | `/v1/retrieve` | ● `GET /?q=&scope=&limit=`、`GET /views/:dim` | 语义 + 关键词 + 视图 |
| 审计 | `/v1/memory` | ● `GET /`、● `GET /:id`、● `PATCH /:id`、● `GET /:id/versions`、● `GET /evidence/:eid` | 查看/溯源/修正 |
| 遗忘 | `/v1/forget` | ● `POST /preview`、● `POST /commit`、● `GET /receipts/:id` | 预览与提交分离 |
| 回执 | `/v1/receipts` | ● `GET /:id`、● `GET /turn/:turnId` | 注入回执查询 |
| 同步 | `/v1/sync` | ● `POST /pull`、● `POST /push`、● `POST /ack` | 事件游标 |
| 候选思想 | `/v1/candidates` | ● `GET /`、● `POST /:id/confirm`、`POST /:id/edit`、`POST /:id/ignore` | P1 完整 |
| 系统 | `/v1/system` | ● `GET /health`、`GET /metrics`、`GET /settings`、`PATCH /settings` | 仅本机/LAN 可访问 |

### 5.2 契约治理（防双端分叉）

- 唯一真相：`packages/contracts` 中的 Zod schema。
- 由 schema 生成 OpenAPI 与类型化客户端 SDK，两端只允许通过 SDK 调用。
- **P0 第一周冻结**：字段只增不改；删改字段视为 breaking，走 `/v2`。
- CI 校验：schema 变更必须同时更新契约版本号与变更记录，否则构建失败。

### 5.3 统一错误封装

```json
{ "error": { "code": "EVIDENCE_UNRESOLVED", "message": "证据不可解析", "retryable": false, "detail": {} } }
```

| code | 语义 | 前端行为 |
|---|---|---|
| `EVIDENCE_UNRESOLVED` | 记忆证据缺失 | 该条不展示为「依据」 |
| `FIDELITY_FAILED` | 保真度未通过 | 档案中标记待复核 |
| `PRIVACY_BLOCKED` | 敏感网关拦截 | 明示「含仅本地内容」 |
| `BUDGET_EXCEEDED` | 预算闸门 | 顶部额度提示 + 降级标识 |
| `CONFLICT_UNRESOLVED` | 存在未仲裁冲突 | 双条展示并高亮 |
| `FORGET_PENDING_ACK` | 有设备未确认删除 | 条目隐藏 + 「删除中」 |
| `OFFLINE_NO_CACHE` | 离线且无缓存 | 明示不可检索，不编造 |
| `RATE_LIMITED` | 质询/请求超限 | 静默跳过，不提示 |

### 5.4 幂等与重试

- 所有写请求带 `Idempotency-Key`（客户端生成 ULID）。
- `POST /turns` 幂等键 = `session_id + client_turn_id`，重放返回同一 turn。
- 同步推送按 `event_id` 去重，天然幂等。

## 6. 存储与读写映射

> 表结构以 04 为准，此处只标读写关系与一致性要求。

| 用例 | 读 | 写 | 一致性 |
|---|---|---|---|
| 语境构建 | `memory_entries` / `evidence` / `tensions` / 向量 / FTS | — | 读己之写 |
| 注入 | 同上 | `injection_log` | 强（与 turn 同事务） |
| 生成 | — | `events(turn)` / `llm_tasks` | 强（流结束落库） |
| 摘要 | `events` | `conversation_memories` / `memory_entries(proposed)` / `thought_candidates` | 最终一致 |
| 修正 | `memory_entries` | `events(correction)` / 新版本行 | 强 |
| 遗忘 | `memory_refs` | `events(forget)` / `tombstones` / 级联 | 强 + 跨端最终一致 |
| 检索 | FTS / 向量 / `edges` | — | 允许 200ms 内延迟 |
| 视图渲染 | 投影表 | — | 允许重建 |

**投影原则**：任何投影表都可以被删除并重放事件重建。写出投影的代码必须是幂等的（`INSERT OR REPLACE` + 版本号或 `ON CONFLICT DO UPDATE`）。

## 7. 多端同步

### 7.1 模型：日志复制，不是状态合并

```
事件不可变 → 同步 = 把对方的日志追加到我这里 → 各自重放投影
```

因此**不存在事件冲突**，只存在投影时序差异。这是选择「一切皆事件」的直接红利。

### 7.2 标识与时序

| 字段 | 作用 |
|---|---|
| `event_id` (ULID) | 全局唯一、时间可排序 |
| `device_id` | 生成设备 |
| `device_seq` | 设备内单调递增，用于断点续传 |
| `lamport` | 跨设备逻辑时钟，用于「同时发生」的稳定排序 |
| `recorded_at` | 本机写入时间（双时态之一） |

排序规则：`(lamport, device_id, event_id)` 全序。

### 7.3 拉取与推送

- `POST /sync/pull {cursor, limit}` → 返回 `event_id > cursor` 的事件批 + 新游标。
- `POST /sync/push {events[]}` → 按 `event_id` 去重后追加，返回被接收的 id。
- 手机离线：本地队列 + 本地游标；上线后先 pull 再 push。

### 7.4 需要合并的少量状态

事件不需要合并，但**投影上的用户操作状态**需要：已读、置顶、面板折叠。统一策略 LWW（`updated_at` + `device_id` 决胜），且这些状态**不是记忆**，不进审计。

### 7.5 遗忘的跨端传播

`forget` 是事件；其他设备收到后执行本地级联，回 `ack` 事件。超时未 ack 的设备，在服务端标记，条目在**所有端强制隐藏**（I6），直到 ack 到达。回执汇总各端状态。

### 7.6 大对象

音频、图片、模型向量默认**不随事件同步**，按 `sha256` 引用；需要时走单独的 blob 通道（P2）。手机端只需文本与索引。

## 8. 失败模式与降级矩阵

| 故障 | 检测 | 降级行为 | 用户可见 |
|---|---|---|---|
| 云端 LLM 超时/5xx | 20s 超时 + 熔断 | 重试 1 次 → 本地 Ollama → 纯检索回答 | 「已降级，未使用云端模型」 |
| 预算耗尽 | 闸门 | 停 T2；对话转 T1 简化 | 顶部额度条 |
| 本地嵌入不可用 | 启动自检 | 仅 BM25 + 精确匹配 | 「语义检索不可用」 |
| 向量索引损坏 | 维度校验/查询异常 | 后台重建，期间 BM25 | 设置页提示 |
| SQLite 写失败 | `busy_timeout` 后仍失败 | 写入本地 journal，稍后补偿 | 「保存失败，已暂存」 |
| 手机离线 | 心跳失败 | 本地缓存 + 队列 | 离线角标 |
| PC 关机 | 连接失败 | 手机只读最近缓存 | 「电脑不在线」 |
| 隐私扫描命中 | 网关 | 阻断该次上云并转本地模式 | 「含仅本地内容，已阻断」 |
| 证书不受信 | 连接错误 | 进入配网引导 | 引导页 |
| 投影不一致 | 定时对账（checksum） | 从事件重放修复 | 无感 |

**对账**：每小时抽样 100 条记忆条目，校验能否由事件重放得到；不一致则重建该分区并记日志（对应 00 中「watchdog + 对账」思路）。

## 9. 技术选型初判

> 选型原则：减少语言与进程数量、减少运维、提高契约一致性。P0 的一切选择都为「双端一周内能并行开工」服务。

| 关注点 | 选择 | 备选 | 理由 |
|---|---|---|---|
| 语言 | TypeScript（Node 22） | Python | 前后端同语言，契约类型共享；AI 能力全走 HTTP，不需要 Python 生态 |
| API 框架 | Fastify 5 | Hono / Express | 性能好、SSE 简单、生态成熟 |
| 契约 | Zod → OpenAPI → 生成客户端 | 手写 DTO | 单一真相，双端零分叉 |
| 数据库 | SQLite（WAL）+ FTS5 + sqlite-vec | LanceDB / Chroma | 单文件、零运维、事务与审计同库，备份即拷贝 |
| ORM/迁移 | Drizzle（schema + migration），投影用原生 SQL | Prisma / 全原生 | 复杂聚合 SQL 更直观，迁移可审阅 |
| 任务队列 | SQLite `jobs` 表 + 进程内 worker | Redis + BullMQ | 单用户不需要外部中间件 |
| 前端 | React 19 + Vite + TanStack Query + Tailwind | Next.js | 纯本地 SPA，无 SSR/SEO 需求 |
| 双端形态 | **一套响应式 Web 代码** | 两套独立前端 | D3 双端并行的成本控制关键（ADR-0004） |
| PC 外壳 | P0 浏览器访问；P2 起可选 Tauri | Electron | 先省一条构建链；Tauri 体积小 |
| 手机形态 | PWA | 原生 App | 安装成本低，与 PC 同代码；能力限制在 06 处理 |
| 流式 | SSE | WebSocket | 单向流足够，穿透代理更简单 |
| 本地嵌入 | ONNX Runtime + `bge-small-zh-v1.5` | 云端 embedding API / `bge-m3` | 隐私 + 成本 + 速度；中文短文本够用 |
| 云端模型 | 适配器（OpenAI 兼容 / Anthropic / Ollama） | 直连单一供应商 | 防锁定，便于 08 做路由 |
| 静态加密 | SQLCipher（首选）/ 字段级 AES-GCM（兜底） | 明文 | 见 §9.2 风险 |
| 测试 | Vitest（单测/契约）+ Playwright（E2E） | Jest | 快、与 Vite 同栈 |
| 构建 | pnpm workspace + tsup | Turborepo | 规模不需要复杂编排 |

### 9.1 为什么是「一套前端」而不是「两套」

双端并行最大的风险是两份业务逻辑漂移（R13）。一套响应式前端 + 两套布局，把「并行」变成「两个入口共用一份实现」，同时仍满足 D3 的「两端同时可用」。代价是手机端要接受 PC 组件的裁剪，这正好符合 01 的功能分档。

### 9.2 待验证的技术风险

| # | 风险 | 验证方式 | 兜底 |
|---|---|---|---|
| T1 | `sqlite-vec` 与 SQLCipher 编译/运行兼容性 | 第一周做最小验证程序 | 退回字段级加密 + 明文向量（向量本身不还原原文） |
| T2 | 手机安装自签证书的可行性与摩擦 | 真机走一遍二维码引导 | 降级为网页版，离线队列推迟 |
| T3 | 本地 ONNX 嵌入在低配 PC 的吞吐 | 1 万条文本批测 | 改云端 embedding（仅文本，脱敏后） |
| T4 | iOS PWA 的后台限制（无 Background Sync） | 真机验证 | 前台同步 + 打开即补传 |
| T5 | SSE 在部分移动浏览器的长时间连接稳定性 | 真机 10 分钟长对话 | 分段重连 + `resume_cursor` |

## 11. 可观测性与运维

| 项 | 做法 |
|---|---|
| 日志 | JSONL，字段含 `trace_id`（turn_id 或 event_id）、`component`、`code`、`duration_ms`；保留 14 天 |
| 追踪 | 一轮对话一个 `trace_id`，串起检索→注入→生成→落库→摘要 |
| 指标 | `GET /v1/system/metrics`：P50/P95 延迟、注入条数、token 与成本、错误码计数、队列积压 |
| 成本 | `llm_tasks` 为唯一账本，按天聚合；预算闸门读同一张表 |
| 告警 | 仅本地：设置页红点 + 日志。**不发送任何外部告警** |
| 对账 | 每小时抽样校验投影；每周全量重建一次（低峰期） |
| 备份 | 每日快照，保留 7 份；恢复流程写在 09 |

## 12. 安全边界（详见 06）

- 静态：数据库加密，密钥存系统钥匙串。
- 传输：局域网 TLS + 设备令牌；默认不监听公网。
- 出口：所有外部请求经 `llm-gateway`，经 `privacy-gateway` 扫描；`local_only` 一律阻断。
- 身份：无账号体系，只有设备配对。
- 遥测：无。
- 审计：`llm_tasks` 记录每次外呼的层、模型、token、成本、输入哈希；不记录明文请求体（避免二次泄露）。
