## 0. 目标与边界

### 0.1 目标

| 目标 | 可验证标准 |
|---|---|
| 本地、离线可用 | 断网时关键词与向量检索仍可用 |
| 解析正确 | 支持格式解析成功率 ≥95% |
| 分块保上下文 | 章节、表格、代码边界正确率 ≥90% |
| 混合召回 | FTS + 向量 + 图三路，任一单路不可用不影响基本可用 |
| 可重建 | 删掉全部索引可从源文件与事件重建，结果一致 |
| 确定性 | 同一查询 + 同一数据 = 同一结果顺序 |
| 快 | 1 万文档 P95 ≤200ms；10 万文档 P95 ≤500ms |

### 0.2 边界

- 本文**做**：文件解析、归一、分块、去重、实体抽取、索引、检索、视图。
- 本文**不做**：注入打分、预算裁剪、冲突判定（属 05）。
- 本文**不做**：云端检索、重排大模型（P0 不引入 reranker）。
- 解析范围：P0 支持文本型 PDF、Office、Markdown、CSV、代码；扫描件标记 `needs_ocr`，图片只索引元数据。OCR、音视频转写不在 P0。

### 0.3 与注入的分工

```
retriever  ：找候选（宁多勿漏，recall 优先）
injector   ：选与裁（precision 与预算优先，见 05 §4）
```

两者共用同一套索引，但排序目标不同：检索追求召回，注入追求相关与不冗余。

## 1. 检索架构

### 1.1 三路通道

```
query
 ├─ ① 关键词通道：FTS5 (trigram) → BM25
 ├─ ② 语义通道：本地嵌入 → vec0 近似最近邻
 └─ ③ 图通道：从命中的实体/记忆出发，1–2 跳扩展
        │
        └─► 融合（RRF）→ 过滤 → 排序 → 分页
```

三路独立执行，任何一路异常都降级为「该路返回空」，不阻断整体。

### 1.2 各通道职责

| 通道 | 擅长 | 不擅长 | 主要参数 |
|---|---|---|---|
| 关键词 | 精确术语、人名、编号、代码 | 同义改写、口语 | `bm25` 权重、trigram |
| 语义 | 同义、跨表述、模糊回忆 | 专有名词精确匹配 | top-k、余弦阈值 |
| 图 | 关联发现、社群、引用链 | 冷启动（无边） | 跳数、边权阈值 |

### 1.3 索引对象（P0）

| 对象 | 关键词 | 向量 | 图 |
|---|---|---|---|
| `turns` | `fts_turns` | `vec_event` | 否 |
| `memory_entries` | `fts_memory` | `vec_memory` | `edges` |
| `conversation_memories` | 复用 `fts_turns` 来源 | 可选 | 否 |
| `assets`（P0） | `fts_chunk` | `vec_chunk` | `edges` |

> `chunks` 的 FTS/向量索引在 P0 迁移中新增；命名与字段必须同步回写 04，保持「表结构单一真相」。

### 1.4 wiki-first 递归检索（P1，ADR-0009）

`chunks.chunk_type` 取 `source`（原文切块）或 `wiki`（编译条目整条入向量）。两类内容**共用同一 embedding 模型与维度**（I19），否则相关性不可比。

```
query
 ├─ ① 先召回 chunk_type='wiki'（从 v_wiki_active 取，I16/I17）
 │      └─ 相关性 ≥ θ_wiki（初值 0.75）→ 直接返回，带来源与 page_id
 └─ ② 低于阈值 → 召回 chunk_type='source' 兜底（I20）
        └─ 仍不足 → 走既有 FTS + 向量 + 图三路
```

规则：

- wiki 条目**整条入向量**，不二次切块；超长时按"摘要 + 正文段落"切，保留标题作公共前缀。
- 原文切块按结构切（标题/章节/函数），不按固定 token 硬切（07 §9.3）。
- wiki 命中时仍需带 `page_id` + evidence；`v_wiki_active` 已过滤 stub 与无证据页。
- 递归检索只用于**世界知识**；用户知识仍走 §1.1 三路 + 05 注入管线，不混排。
- θ_wiki 初值 0.75，用金标集校准（10 §7.1）；调参遵循一次一个参数原则。

**反例**：wiki 页相关性 0.6 就用它回答、且不再查 source——这违反 I20，会让未编译充分的条目挤掉原文证据。

## 2. 查询处理

### 2.1 输入

```ts
type RetrieveRequest = {
  q: string;
  scope?: ('memory' | 'turn' | 'asset')[];   // 默认 memory + turn
  filters?: {
    type?: MemoryType[];
    layer?: ('L1'|'L2'|'L3')[];
    status?: ('active'|'corrected'|'superseded')[];
    from?: number; to?: number;               // 时间范围
    tag?: string; entity?: string;
  };
  limit?: number;                             // 默认 20，上限 100
  hops?: 0 | 1 | 2;                           // 图扩展，默认 0
};
```

### 2.2 处理步骤（P0 不调用 LLM）

1. **归一化**：去首尾空白、压缩连续空白、小写化英文、保留中文原样。
2. **切词**：中文用 trigram 由 FTS5 处理；英文按空格与标点切分。
3. **实体识别（轻量）**：查 `entities.name` 做最长匹配，命中则用于图通道与过滤，不调模型。
4. **时间解析（轻量）**：识别「上个月」「9 月」等，转成 `from/to`；失败则忽略。
5. **通道并行**：三路查询并发执行，各自超时 150ms。
6. **融合**：RRF 合并。
7. **过滤**：应用 `filters` 与隐私（见 §5）。
8. **分页**：游标分页，不返回总数（需要时单独 `count` 接口）。

### 2.3 空查询

- `q` 为空且无 filters → 返回最近更新的 N 条（按 `updated_at`），用于「首页」。
- `q` 为空但有 filters → 纯过滤查询。
- 禁止空查询触发图扩展。

## 3. 索引构建

### 3.1 写入路径

```
事件提交（事务内）
   └─ 投递 jobs: embed(event) / index_fts(event)
        └─ worker 批量处理（batch ≤32）
             ├─ 生成向量 → vec_event / vec_memory
             └─ 写 FTS（fts_turns / fts_memory）
```

- 索引是**异步**的；写入成功后 ≤2s 内可检索（SLA）。
- 索引失败不影响主流程，作业重试 3 次后进入死信，界面提示「部分内容暂不可检索」。

### 3.2 嵌入模型

| 项 | 值 |
|---|---|
| 模型 | `bge-small-zh-v1.5`（512 维） |
| 运行 | ONNX Runtime，本地 CPU |
| 查询前缀 | `为这个句子生成表示以用于检索相关文章：` |
| 批大小 | 32（写入）/ 1（查询） |
| 归一化 | L2 归一化后存 |

模型记录在 `settings.embedding_model`；**更换模型必须重建全部向量**，因为维度与空间不兼容。

### 3.3 增量与重建

| 操作 | 行为 |
|---|---|
| 新事件 | 追加向量 + FTS |
| 记忆修正 | 更新 `vec_memory` 与 `fts_memory`（按 `memory_id` 覆盖） |
| 遗忘 | 删除向量 + FTS + 边 |
| 全量重建 | `pnpm rebuild --projector index`，分批 1000 条，可中断续跑 |
| 校验 | 每周抽样 100 条，对比向量存在性与 FTS 可检索性 |

### 3.4 一致性

- `vec_*` 与 `fts_*` 不是事务性同步的，允许短暂不一致。
- 检索结果在返回前做「存在性校验」：向量命中的 id 必须仍存在于 `v_injectable*` 或 `turns`，否则丢弃。
- 这条校验让索引滞后不会导致「搜到已删除内容」。

## 4. 融合与排序

### 4.1 RRF 融合

```
score(d) = Σ_{r ∈ 通道} 1 / (k + rank_r(d))，k = 60
```

| 通道 | 权重 |
|---|---|
| 关键词 | 1.0 |
| 语义 | 1.0 |
| 图 | 0.6 |

- 权重只作用于该通道贡献，不改变 RRF 公式结构。
- 未命中的通道不贡献，不做惩罚。
- 同分时按 `(updated_at desc, id asc)` 决胜，保证确定性。

### 4.2 轻量加权（仅检索层）

融合后再做一次可解释的加权，用于「明显该靠前」的情况：

```
final = rrf × (1 + 0.15×exact_match + 0.10×recency + 0.10×type_boost)
```

| 项 | 条件 |
|---|---|
| `exact_match` | 查询串完整出现在标题/正文（大小写不敏感） |
| `recency` | `exp(-Δdays/90)` |
| `type_boost` | 用户显式记住的 fact/commitment +0.1 |

**禁止**在此层做语义重排或调用模型——排序必须可解释、可复现。

### 4.3 去重

- 同一 `memory_id` 多路命中：取最高分，合并通道标记。
- 同一 `content_hash` 的多条记忆：保留最新 `tx_from`，其余折叠并标注「另有 N 个版本」。

## 5. 过滤

### 5.1 硬过滤（任何情况都生效）

| 过滤 | 实现 |
|---|---|
| 已遗忘 | 排除 `tombstones` 命中项 |
| 已确认重复 | `documents.duplicate_of` 非空默认排除；`include_duplicates=1` 可查 |
| 非当前版本 | `tx_to IS NOT NULL` 排除（除非查询显式要历史） |
| 保真度 | 默认排除 `fidelity` 非 `pass/not_applicable` |
| 隐私 | 若当前出口是云端，排除 `local_only`（出网前由 06 再兜底一次） |

### 5.2 软过滤（用户可选）

- 类型、层、状态、时间范围、标签、实体。
- 软过滤不改变排序公式，只缩小集合。

### 5.3 历史查询

显式指定 `as_of` 时：

- 允许返回 `corrected` / `superseded`；
- 结果需带 `version` 与 `valid_from/to`，界面标注「历史版本」。

## 6. 图扩展

### 6.1 触发

仅当 `hops ≥ 1` 且存在种子（关键词或向量命中）：

```
种子（top-5） → 1 跳邻居 → （可选）2 跳 → 合并 → 重新排序
```

### 6.2 规则

| 项 | 值 |
|---|---|
| 边类型 | `same_topic` / `cites` / `co_entity` / `related` |
| 排除边 | `contradicts`（冲突不作为「相关」推荐，避免误导） |
| 权重阈值 | ≥0.4 |
| 节点上限 | 200 |
| 权重衰减 | 每跳 ×0.5 |
| 去重 | 已在种子中的节点不重复加入 |

### 6.3 输出标记

每个结果带 `channels: ['fts'|'vec'|'graph']` 与 `hop`，便于界面解释「为什么它出现了」。

## 7. 虚拟目录（视图引擎）

### 7.1 视图是查询，不是文件

```
view := groupby(dim) | filter(pred) | order(key) | limit(n)
```

- 视图**不落盘**、不复制文件、不改物理路径。
- 每次渲染都是一次查询；结果可缓存 30s（写操作即失效）。
- 视图定义存 `view_defs`，支持内置与用户自定义。

### 7.2 维度

| dim | 分组键 | 典型用途 |
|---|---|---|
| `time` | `YYYY/MM`（按 `recorded_at` 或 `mtime`） | 按时间回看 |
| `ext` | 扩展名归类（文档/表格/图片/代码） | 按类型 |
| `tag` | `tags.name` | 按主题 |
| `entity` | `entities.name` | 按人/机构/概念 |
| `project` | tag(kind=project) | 按项目 |
| `source` | `origin`（capture/conversation/import） | 按来源 |
| `custom` | 用户给定 predicate | 任意组合 |

### 7.3 视图定义示例

```json
{
  "name": "按主题看文档",
  "dim": "tag",
  "predicate": {
    "target": "memory",
    "status": "active",
    "fidelity": ["pass", "not_applicable"]
  },
  "order": { "field": "updated_at", "dir": "desc" },
  "limit": 50
}
```

对应的 SQL 形态（伪代码）：

```sql
SELECT t.name AS group_key, COUNT(*) AS cnt
FROM tag_links l JOIN tags t ON t.id = l.tag_id
JOIN memory_entries m ON m.id = l.target_id
WHERE l.target_type = 'memory' AND <predicate>
GROUP BY t.name
ORDER BY cnt DESC, t.name ASC
LIMIT :limit;
```

### 7.4 树形渲染

目录树必须**懒加载**：

1. 根层只查一级分组的计数（`GROUP BY`）。
2. 展开某节点时再查该组的子分组或条目（`LIMIT 50 + cursor`）。
3. 单节点子项超过 500 时显示「仅显示前 500，请缩小范围」，不做无限滚动到底。
4. 计数使用近似值（`COUNT(*)` 在万级数据可接受；百万级改为估算）。

### 7.5 四类视图

| 类型 | 生成方式 | 阶段 |
|---|---|---|
| 规则视图 | mtime / ext / 路径关键词 | P0 |
| 标签视图 | `tag_links` 分组 | P0 |
| 实体视图 | `entity_links` 分组 | P4 |
| 关联视图 | 图扩展（§6），以某条为种子 | P4 |

> P0 同时有文件与记忆：文件视图按目录、类型、时间、标签；记忆视图按时间、类型、标签。两者共用同一 DSL 与分页规则。

### 7.6 分页

- 游标 = `(sort_value, id)` 的 base64 编码。
- 禁止 `OFFSET` 分页（万级数据会退化）。
- 返回 `next_cursor`，无更多时为 `null`。

## 8. 性能与容量

| 场景 | 数据量 | P50 | P95 | 说明 |
|---|---|---|---|---|
| 关键词检索 | 1 万文档 | 15ms | 40ms | FTS5 |
| 向量检索 | 5 万向量 | 30ms | 90ms | vec0 top-20 |
| 混合检索 | 1 万文档 | 40ms | 120ms | 三路并发 |
| 混合检索 | 10 万记忆 | 90ms | 300ms | 需调 `nprobe` |
| 视图根层 | 1 万文件 | 60ms | 200ms | GROUP BY |
| 视图展开 | 单组 500 项 | 20ms | 60ms | 分页 |
| 图 1 跳 | 10 万边 | 20ms | 70ms | 索引 `edges(src_id)` |

索引补齐（04 未列出的，实施时新增）：

```sql
CREATE INDEX idx_edges_src ON edges(src_type, src_id, weight DESC);
CREATE INDEX idx_edges_dst ON edges(dst_type, dst_id, weight DESC);
CREATE INDEX idx_tag_target ON tag_links(target_type, target_id);
CREATE INDEX idx_entity_target ON entity_links(target_type, target_id);
```

容量上限：单用户 3 年 100 万事件时，向量表约 2GB（512 维 float32）。超过后启用 IVF 分区或降维，写进 ADR。

## 9. 文件解析、分块与去重（P0 主干）

### 9.1 支持格式与解析器

| 格式 | 解析器（P0 实现） | 输出单元 | 状态 |
|---|---|---|---|
| txt / md / csv | 自研文本读取 | 段落 | 已实现 |
| pdf（文本型） | pdfjs-dist（沙箱子进程） | 页 → 段落；保留页码 | 已实现 |
| pdf（扫描件） | — | 标记 `needs_ocr`，不阻塞 | 仅标记 |
| docx | mammoth（沙箱子进程） | 段落 | 已实现 |
| xlsx / xls | SheetJS（沙箱子进程） | Sheet → CSV 行；上限 50 Sheet / 5000 行 | 已实现 |
| pptx | JSZip + DrawingML 文本（沙箱子进程） | Slide → 段落；上限 200 页 | 已实现，暂不抽备注 |
| 代码 | tree-sitter | 文件 → 函数/类 | P1 |
| 图片 | 元数据（EXIF/尺寸） | 资产条目 | P1 |

失败码固定为：`unsupported`、`corrupt`、`encrypted`、`needs_ocr`、`timeout`、`too_large`、`empty`。

### 9.2 归一化

1. Unicode NFC；统一换行；压缩连续空白。
2. 去页眉页脚：同页重复出现的短行，按文档统计剔除。
3. 断词修复：行尾连字符拼接（仅西文）。
4. 保留原始字符偏移，供证据定位。
5. 表格保留「表头 + 行」结构，不把单元格拍平成一行文本。

### 9.3 分块策略

| 类型 | 策略 | 上限 | 重叠 |
|---|---|---|---|
| 结构化文档 | 按标题层级切，超长再按段落 | 800 tokens | 15% |
| 表格 | 一个表头 + N 行，跨块重复表头 | 600 tokens | 0（按行对齐） |
| 代码 | 函数/类为单位，超长按语句块 | 800 tokens | 10% |
| 对话/邮件 | 按说话人/段落 | 600 tokens | 15% |
| 无结构长文 | 段落聚合 | 600 tokens | 15% |

规则：

- 最小块 100 tokens；过短则与相邻块合并。
- 每块前置**结构面包屑**：`文档标题 > 一级标题 > 二级标题`，不调用模型。
- 保存 `parent_chunk_id`：检索命中子块时可回扩到父块（small-to-big）。
- 证据定位必须能回到 `char_start/char_end` 或 `page_from/page_to`。
- 不跨章节合并；不把两个表格拼成一块。

### 9.4 去重

| 层级 | 方法 | 动作 |
|---|---|---|
| 文件级精确 | SHA-256 | 同一资产只解析一次 |
| 文件级近似 | SimHash / MinHash（归一化文本） | 标记 `near_duplicate`，保留主副本，不删除 |
| 块级 | 文本指纹 + 长度阈值 | 标记重复块，检索时降权 |

规则：

- 去重只标记，不物理删除；主副本选择顺序：路径更短 → mtime 更新 → 内容更长。
- 近似重复阈值默认 0.9，需用金标集校准；误杀率 >5% 即回退阈值。
- 同一文件内容变更按新版本处理，旧版本保留在 `assets` 历史中，不覆盖证据。
- 重复判定结果写入 `organize_suggestions`，由人确认后才改变集合归属。

### 9.5 实体与元数据抽取

- 本地规则优先：日期、路径、项目名、代码符号、文档标题。
- 本地 NER 次之：人名、机构、地点；低置信度不写入 `active`。
- 模型只处理歧义与跨语言；每次调用记录 `llm_tasks`。
- 实体归并只生成建议（别名、同一实体），不自动合并。
- 元数据缺失就留空，不猜作者、不猜日期。

### 9.6 写入与幂等

```
asset(hash, path, mtime)
  → document(asset_id, parse_status)
  → chunk(document_id, ordinal, char/page range)
  → fts + vec + graph
  → ingest_jobs(state)
```

- 幂等键：`source_id + locator + sha256`。
- 解析成功但索引失败：保留 document，作业重试，不重复解析。
- 源文件哈希未变：跳过解析，只校验索引是否存在。
- 删除/移动：先标记 `missing`，连续 3 次对账仍缺失才 `deleted`，索引保留 tombstone。

### 9.7 质量闸门

| 项 | 方法 | 目标 |
|---|---|---|
| 解析覆盖 | 支持格式抽样 200 份 | ≥95% |
| 边界正确 | 人工标注 50 份，检查章节/表格/代码切分 | ≥90% |
| 去重精确 | 标注 100 对，检查误判 | ≥95% |
| 去重召回 | 注入已知重复集 | ≥80% |
| 证据可定位 | 随机 100 块回查原文 | 100% |

## 10. 评测

| 指标 | 定义 | 目标 |
|---|---|---|
| Recall@10 | 金标查询的前 10 结果包含标准答案的比例 | ≥85% |
| MRR | 标准答案的平均倒数排名 | ≥0.65 |
| 解析成功率 | 成功解析 ÷ 支持格式文件 | ≥95% |
| 分块边界正确率 | 抽样中章节/表格/代码切分正确比例 | ≥90% |

| 实体准确率 | 正确实体 ÷ 抽取实体 | ≥85% |
| 多跳证据完整率 | 2 跳问题中证据链完整比例（P1） | ≥70% |
| 视图正确性 | 分组计数与全量扫描一致 | 100% |
| 索引延迟 | 写入到可检索 | P95 ≤2s |

| 降级可用性 | 停用向量后关键词仍可用 | 100% |
