## 0. 安全目标与信任边界

### 0.1 保护对象（按重要性）

| 优先级 | 资产 | 泄露后果 |
|---|---|---|
| 1 | 事件正文、记忆条目正文 | 私密对话与判断被第三方读取 |
| 2 | 证据原文与文件路径 | 可还原生活轨迹与工作内容 |
| 3 | 行为信号（检索词、点击、审计动作） | 暴露关注点与心理状态 |
| 4 | 模型调用记录（`llm_tasks`） | 暴露话题分布与使用强度 |
| 5 | 设备令牌与加密密钥 | 直接导致 1–4 全部失守 |

### 0.2 信任边界

```
[可信] 本机进程 · 本机数据库 · 系统钥匙串 · 用户自己的手机
   │
   │  ← 设备令牌 + 局域网 TLS（可审计、可撤销）
   │
[半可信] 局域网内的其他设备（同一 WiFi 下的陌生设备）
   │
   │  ← 出网网关：隐私分级 + 脱敏 + 扫描（默认拒绝）
   │
[不可信] 公网 · 云端模型供应商 · 任何第三方服务
```

**明确假设**：云端模型供应商可能记录请求；局域网可能被嗅探；手机可能丢失；PC 可能中马。系统不假设任何一方是善意的。

### 0.3 威胁模型

| # | 威胁 | 场景 | 主要缓解 |
|---|---|---|---|
| T1 | 云端留存 | 供应商记录 prompt 用于训练 | 分级 + 脱敏 + `local_only` 硬阻断 |
| T2 | 局域网窃听 | 同网段抓包 | TLS + 令牌 + 默认不监听 LAN |
| T3 | 手机丢失 | 未锁屏或令牌被提取 | 令牌可远程撤销 + 短期有效 + 只读权限 |
| T4 | 本机恶意软件 | 读取数据库文件 | 静态加密 + 密钥在钥匙串 |
| T5 | 日志泄露 | 正文进了日志或错误堆栈 | 日志白名单 + 禁止正文（09 §9） |
| T6 | 备份泄露 | 备份被拷走 | 备份同加密 + 保留期上限 |
| T7 | 同步污染 | 不可信设备推送伪造事件 | 设备白名单 + 事件哈希链 + 拒绝未知设备 |
| T8 | 遗忘不彻底 | 向量/备份残留 | 七步级联 + 墓碑 + 备份披露 |
| T9 | 截图/导出外流 | 用户自己分享 | 系统无法防，明确告知 |
| T10 | 旁观者被录制 | 手机/电脑录音录到第三人 | 默认不存原始音频 + 提示音 + 系统录制指示 + 场景禁区 |
| T11 | 手机/电脑被夺取 | 物理接触读取本地库 | 全盘/字段加密 + 令牌撤销 + 系统锁屏 |
| T12 | MCP 内容注入 | 外部文档/工具描述含恶意指令 | 内容视为数据；写操作需确认；连接器白名单 |

## 1. 隐私分级

### 1.1 两级模型

只保留两级，避免复杂度失控：

| 级别 | 含义 | 允许出网 | 允许 LAN 同步 |
|---|---|---|---|
| `llm_ok` | 可送云端模型 | 是 | 是 |
| `local_only` | 仅本机 | **否** | 是（仅自己的设备） |

> 为什么不是三级：`secret` / `sensitive` 这类中间档在实际使用中无法稳定判定，最终都会退化成「全都不许」或「全都允许」。两级 + 目录级默认，是唯一能被人真正执行的粒度。

### 1.2 作用域与优先级

`privacy_labels(scope, target, level)` 支持四种作用域，**就近覆盖**：

```
memory > event > asset > directory > global
```

- `global`：默认 `llm_ok`。
- `directory`：路径前缀，例如 `D:\资料\医疗\` → `local_only`。
- `asset` / `event` / `memory`：单条覆盖。

### 1.3 标签传播（关键规则）

派生对象**继承最严格的来源标签**：

| 派生关系 | 规则 |
|---|---|
| event → memory | 取该事件及全部 evidence 来源中最严格者 |
| event → conversation_memory | 摘要中只要含一条 `local_only`，整条摘要即为 `local_only` |
| event → embedding | 向量继承源级别；`local_only` 的向量只存本地、不参与任何出网计算 |
| memory → summary / preference | 同上 |
| asset → chunk（P3） | 同上 |

**禁止降级**：任何自动流程不得把 `local_only` 改成 `llm_ok`；只能由用户在档案页手动逐条放行，且放行是一次性的（下次仍需确认）。

### 1.4 默认值

| 项 | 默认 |
|---|---|
| 全局 | `llm_ok` |
| 新建目录规则 | 用户显式添加 |
| 手机捕捉 | 继承全局；语音默认 `llm_ok`，可一键改 `local_only` |
| 备份 | 与源同级 |

## 2. 敏感网关

### 2.1 位置

所有出网请求（对话、摘要、打标、嵌入 API）必须经过同一个函数：

```
buildOutbound(payload) → scan → (pass | block)
```

网关位于 `llm-gateway` 之前，**不可绕过**（09 §10.3 有静态扫描规则）。

> 阶段说明：P0 只写入隐私标签并保留扫描接口（不阻断出网），目的是先跑通知识库闭环；**P2 起强制启用全部检查**。标签必须从第一天就正确，否则 P2 无法追溯历史数据。

### 2.2 扫描管线

| 步 | 检查 | 命中行为 |
|---|---|---|
| G1 | 解析 payload 中引用的 `event_id` / `memory_id` / `asset_id` | 收集引用清单 |
| G2 | 查 `privacy_labels` 与继承标签 | 任一 `local_only` → 阻断 |
| G3 | 路径替换：绝对路径 → `sha256(path)[0:12]` | 替换 |
| G4 | 正则脱敏：手机号 / 身份证 / 银行卡 / 邮箱 / IP | 替换为类型占位符 |
| G5 | 敏感词表（用户自定义） | 命中 → 阻断并提示 |
| G6 | 体积与字段白名单校验 | 多余字段直接丢弃，不发送 |

### 2.3 阻断后的行为

阻断不是报错，而是降级：

| 场景 | 降级 |
|---|---|
| 对话注入命中 `local_only` | 转为「本地材料呈现模式」：只展示本地检索结果，不调用云端生成 |
| 摘要任务命中 | 该会话摘要标记 `blocked`，保留原文，等待用户手动处理 |
| 打标任务命中 | 跳过该条，标签置空，不阻断其他条目 |
| 嵌入（本地） | 不受影响；本地计算不算出网 |

界面必须明确显示「本次回答未使用云端模型，原因：含仅本地内容」。**不允许静默降级**。

### 2.4 自动测试

网关必须有固定用例（09 §10）：

- 直接命中：payload 含 `local_only` 的 `event_id`。
- 间接命中：payload 只含摘要 id，但摘要继承自 `local_only`。
- 嵌套命中：JSON 深层字段携带来源 id。
- 分片命中：SSE 分片里夹带来源引用。
- 误杀：全部 `llm_ok` 时必须放行（防止过度阻断）。

## 3. 静态加密

### 3.1 两层密钥

```
主密钥 KEK（系统钥匙串）
   └── 包裹 → DEK（每条事件/会话/资产）
          └── AES-256-GCM 加密正文
```

| 对象 | 加密方式 | 说明 |
|---|---|---|
| `event_payloads.cipher` | DEK + AES-GCM | 每条事件独立 DEK |
| `memory_entries.content` | 数据库级或字段级 | 见 §3.2 |
| 备份文件 | 整包加密 | 用 KEK 派生的备份密钥 |
| 向量 | 默认明文（无论文本） | 需证明不可还原，见 §3.4 |

### 3.2 数据库级 vs 字段级

| 方案 | 优点 | 缺点 | 采用条件 |
|---|---|---|---|
| SQLCipher 全库加密 | 一次到位，索引也加密 | 与 `sqlite-vec` 兼容性未知（T1） | spike 通过则首选 |
| 字段级加密 | 兼容性最好 | 索引/查询字段仍明文 | SQLCipher 不可行时兜底 |

**决策规则**：第一周 spike 结论写入 ADR-0005。无论哪种，`event_payloads` 始终额外做字段级加密——这是遗忘与纵深防御的基础。

### 3.3 密钥生命周期

| 阶段 | 行为 |
|---|---|
| 首次启动 | 生成 KEK，存系统钥匙串；生成备份密钥 |
| 每条事件 | 生成随机 DEK，包裹后存 `crypto_keys` |
| 遗忘 | 销毁 DEK（`wrapped_key=NULL`，`destroyed_at` 记录） |
| 轮换 | 每年轮换 KEK，重新包裹所有未销毁 DEK |
| 丢失 | KEK 丢失 = 数据不可恢复；必须提供恢复码（用户抄写保存） |

**恢复码**：KEK 的 Shamir 分片或助记词，首次启动时生成一次，要求用户离线保存。没有恢复码就没有灾难恢复，这一点必须写进引导。

### 3.4 向量是否泄露原文

- 嵌入是单向压缩，理论上不可精确还原，但存在成员推断与近似重构风险。
- 结论：`local_only` 的向量**永不出网**；本地存储可接受。
- 若采用 SQLCipher 全库加密，向量自然加密；否则至少在文件系统层做整盘加密（BitLocker / FileVault）作为补偿控制。
- 这条结论写入 06 后不再反复讨论。

## 4. 传输安全与设备

### 4.1 局域网 TLS

- 首次启动生成自签 CA（本地），签发服务器证书。
- 手机扫码安装根证书（一次性），之后浏览器信任。
- 端口默认 8420；`lan=false` 时只绑 `127.0.0.1`。
- 不使用公共 CA，不做端口转发，不默认开启公网。

### 4.2 配对

| 项 | 规则 |
|---|---|
| 配对码 | 6 位数字，10 分钟有效，一次性 |
| 令牌 | 256 位随机，服务端只存哈希（`devices.token_hash`） |
| 权限 | 手机端默认只读；写操作需 PC 端确认（D8） |
| 失效 | 30 天无活动自动要求重配对 |
| 撤销 | PC 端一键撤销，立即生效（`devices.revoked_at`） |

**PWA 的诚实限制**：浏览器无法访问硬件安全区，令牌只能存 IndexedDB。因此：

- 令牌设为**设备绑定 + 短期**（30 天），降低被提取后的窗口。
- 手机丢失时，用户必须在 PC 上撤销；撤销后所有请求 401。
- 不承诺「手机端达到硬件级安全」，写进引导页。

### 4.3 同步安全

- 只接受已配对设备的事件推送（白名单）。
- 每条事件校验 `hash` 与 `prev_hash` 链；断链事件拒收。
- 未知 `device_id` 直接拒绝，不进入投影。
- 大对象（音频/图片）默认不同步；需要时走单独通道并单独授权。

### 4.4 手机/电脑丢失（S0）

| 步骤 | 行为 |
|---|---|
| 1. 标记丢失 | 用户在另一端撤销该设备令牌，立即失效 |
| 2. 本地保护 | 数据库字段级加密 + 系统锁屏；应用不缓存明文 |
| 3. 记忆保全 | 另一端保留完整记忆；丢失端只是入口 |
| 4. 远程登出 | 下次联网时清除该端令牌与本地缓存；不承诺 OS 级擦除 |
| 5. 如实告知 | 说明「已撤销访问」与「无法远程擦除已导出内容」的区别 |

### 4.5 应用更新与回滚

- 应用更新必须签名，安装包可校验。
- 数据库迁移只前进，不自动降级；回滚靠备份，不靠逆向迁移。
- 灰度发布：先内部设备，观察 48 小时再全量。
- 更新失败必须可回到上一版本，且不破坏已有数据。

### 4.6 MCP 连接器安全（v0.4）

| 项 | 规则 |
|---|---|
| 默认权限 | 只读；每个连接器单独授权 scope |
| 内容信任 | 外部内容一律视为**数据**，其中的指令不得触发工具调用 |
| 工具描述 | 连接器白名单 + 人工审核 + 版本与哈希锁定 |
| 写入 | 任何 MCP 写操作必须逐次确认；内容不能代替用户授权 |
| 撤销 | 断开连接器即停止同步，并可清除其派生数据 |
| 隐私继承 | 连接器标记 `local_only` 时，其所有派生对象同标记 |
| 审计 | 每次调用记录连接器、工具、输入摘要、结果状态 |

## 5. 脱敏规则

| 类型 | 正则要点 | 替换 |
|---|---|---|
| 手机号 | 中国大陆 1[3-9]\d{9} | `[PHONE]` |
| 身份证 | 18 位含校验位 | `[ID]` |
| 银行卡 | 16–19 位数字（含空格分组） | `[CARD]` |
| 邮箱 | 常规邮箱 | `[EMAIL]` |
| IP | IPv4/IPv6 | `[IP]` |
| 绝对路径 | 盘符或 `/Users/`、`/home/` | `sha256(path)[0:12]` |
| 自定义 | 用户维护的词表 | `[REDACTED]` |

规则：

- 脱敏在**出网前**执行，不在写入时执行（原文必须保留，审计需要）。
- 脱敏后的文本不得写回数据库。
- 正则必须在测试集上验证误杀率（例如把日期误判为电话）。

## 6. 泄露面清单

| 面 | 风险 | 控制 |
|---|---|---|
| 应用日志 | 正文/路径 | 白名单字段 + 禁止正文（09 §9） |
| `llm_tasks` | 输入哈希可被枚举比对 | 只存哈希，不存原文；哈希加盐 |
| 错误堆栈 | 携带请求体 | 生产环境不返回堆栈；日志中剥离 |
| 数据库文件 | 直接读取 | 静态加密 + 整盘加密 |
| WAL / SHM | 加密不覆盖 | 与主库同目录、同权限；SQLCipher 下同样加密 |
| 备份 | 拷走 | 加密 + 保留期 + 不自动上传 |
| 导出 | 用户主动导出 | 明确提示「导出文件不受系统保护」 |
| 浏览器缓存 | PWA 缓存页面 | 只缓存静态资源，不缓存正文 |
| 屏幕截图 | 系统级 | 无法防护，明确告知 |
| 崩溃转储 | 可能含内存明文 | 关闭自动上传；本地转储加密 |

## 6A. 旁观者隐私与场景禁区（v6 增补）

随身设备与前 12 篇最大的不同：**它会录到别人**。这一节是硬约束，不是建议。

### 6A.1 默认值

| 项 | 默认 | 可配置 |
|---|---|---|
| 原始音频留存 | 不留存 | 可开启，上限 7 天 |
| 公共场景 | 只做本地转写，不长期保留 | 可按场景白名单 |
| 提示音 | 开始录制时播放 | 可关闭（不建议） |
| 系统录制指示 | 由操作系统显示 | 不可伪造、不可隐藏 |
| 说话人身份 | 匿名 A/B | 不做身份识别 |
| 后台摄像头 | 不采集 | 仅显式拍照/选图 |

### 6A.2 场景禁区

检测到以下场景时，停止编码并提示：

- 医疗机构、心理咨询、法律援助；
- 未成年人为主的场景；
- 更衣室、洗手间等私密场所；
- 用户标记为「禁录」的日历事件或地点。

### 6A.3 他人权利

- 任何人可要求用户停止录制；应用内停止按钮与系统权限必须一键生效。
- 不建立他人声纹库，不做跨场景身份关联。
- 他人可识别信息（姓名、电话、证件号）在编码时脱敏，原文不落盘。
- 用户可一键删除某段时间的所有情景与片段（按时间范围遗忘），回执可见。

### 6A.4 组织策略

- 企业/学校可下发「禁用感知」策略，设备强制执行且用户不可绕过。
- 策略变更必须可审计，用户可查看当前生效的策略来源。

> 伦理底线：默认状态是「不记录原始音频」；记录是例外，且必须可感知、可撤回。

## 7. 隐私承诺与边界

### 7.1 承诺（可验证）

1. 无账号、无遥测、无外部上报。
2. `local_only` 内容不出本机（由网关 + 测试强制）。
3. 遗忘有回执，回执披露备份保留期。
4. 所有模型调用可查（`llm_tasks`），不含原文。
5. 数据可整体导出为明文快照（用户主动操作）。

### 7.2 做不到的（必须写进引导与回执）

| 项 | 原因 |
|---|---|
| 撤回已发送给云端的请求 | 供应商侧不可控 |
| 删除用户自己复制/截屏/导出的内容 | 已离开系统边界 |
| 立即清除历史备份中的副本 | 保留期机制决定 |
| 防护已失陷的操作系统 | 恶意软件可读内存 |
| 手机端硬件级密钥保护 | PWA 限制 |
| 删除他人设备上已同步的副本 | 对方设备不在控制范围 |
| 撤回他人已听到/看到的转写内容 | 已离开系统边界 |
| 阻止他人翻拍屏幕 | 物理世界不可控 |

> 隐瞒边界比做不到更危险。首次启动与遗忘回执页必须展示同一份清单。

## 8. 安全自检

| 检查 | 频率 | 失败动作 |
|---|---|---|
| 网关用例全绿（含误杀） | 每次 CI | 阻断发布 |
| `local_only` 外发计数 = 0 | 每日 | 阻断发布 + 审计 |
